# ADR-0001: Модульная архитектура и базовый стек

- Статус: принято
- Дата: 2026-09-26
- Затрагивает: весь проект

## Контекст

Heartbeat — ИИ-студия на KMP для Android, iOS, macOS и Windows. Нужны: изоляция фич, явные контракты поведения,
предсказуемое состояние, полная наблюдаемость (логирование всех действий) и нативный вид на каждой платформе.

## Решение

- Группы модулей `platform-main / core / design-system / features`; фича = `api` + `impl`.
- Поведение фичи — конечный автомат **KStateMachine**, объявленный в `api`. Межфичевое взаимодействие — только через
  `MachineKey` (object) + `MachineRegistry` и публичные события машины. Уточнено [ADR-0004](0004-state-machine.md):
  типизированный `machineSpec { }` в `api`, KStateMachine — движок в `core:state-machine:impl`.
- UI-состояние — **FlowMVI**; навигация — **Decompose**; DI — **Metro**; сеть — **Ktor**; БД — **Room KMP**;
  настройки — **DataStore KMP**; ИИ — **Koog**; ресурсы — **Compose Resources**; логи — **Napier**; lint — **detekt** + ktlint-wrapper + compose-rules.
- Дизайн-система Mission; UI-киты: Material 3 (Android/iOS), compose-fluent-ui (Windows), compose-macos-26-ui (macOS).
- Фича-тоглы — тонкая обёртка над DataStore + внутренний экран управления (пока только локально).

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Koin / kotlin-inject | Metro — compile-time граф, KMP, анвил-подобные контрибуции для api/impl |
| Voyager / navigation-compose | Decompose отделяет навигацию от UI, lifecycle/state-keeper на всех платформах |
| Логика флоу только в MVI-сторе | нет формальной спецификации переходов, сложно связывать фичи |

## Последствия

- Каждая фича публикует явный автомат — он же документация и точка интеграции.
- Инфраструктурные модули обязаны давать логирующие адаптеры, иначе требование «логировать всё» невыполнимо.
- Правила зависимостей проверяются ревью-агентом и (после build-logic) Gradle-проверкой.
