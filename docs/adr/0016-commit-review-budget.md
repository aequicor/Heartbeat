# ADR-0016: Бюджет ревью на отдельный коммит

- Статус: принято
- Дата: 2026-09-27
- Затрагивает: процесс ревью, scripts, GitHub Actions, инструкции агентов

## Контекст

PR должен содержать фичу целиком, а логические коммиты — позволять ревью по шагам.
Для одного коммита выделено 10% условного окна модели в 250 000 токенов.
Измерения 445 Kotlin/KTS-файлов и 18 коммитов показали, что строки и число файлов
не гарантируют соблюдение токенного бюджета.

## Решение

Проверять каждый коммит по [политике](../ai/commit-policy.md): предел 25 000 токенов,
предупреждения свыше 20 000 токенов или 20 файлов. Строки — ориентир, размер PR не ограничен.
Использовать Python ≥3.12 и `tiktoken==0.14.0` только как инструмент разработки/CI.
Метрика — максимум двух кодировок `o200k_base` и `cl100k_base` на фиксированном Git diff.
Подсчёт не использует LLM API и не отправляет код в сеть.

Версия Python-зависимости закреплена в `scripts/requirements-commit-policy.txt`:
это явное исключение для инструмента вне Gradle; зависимости приложения остаются
в `gradle/libs.versions.toml`. Установка инструмента не изменяет зависимости приложения.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему нет |
|---|---|---|---|
| Только 1000 строк / 20 файлов | Просто | Не гарантирует токенный бюджет | Нет прямого измерения |
| Оценка по символам | Без зависимости | Зависит от языка и содержимого | Нет воспроизводимого подсчёта токенов |
| Подсчёт через LLM API | Учитывает конкретную модель и запрос | Ключ, сеть, передача кода | Для текстового diff достаточно локального инструмента |

## Последствия

Нужны Python и первоначальная загрузка словарей. Политика закреплена в `CLAUDE.md`,
процедуре `verify`, локальном скрипте и CI. После публикации workflow обязательность
статуса `Commit size` задаётся в настройках защиты целевой ветки GitHub.
