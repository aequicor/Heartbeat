# ADR-0016: Постоянные секреты профиля и ссылки потребителей

- Статус: принято
- Дата: 2026-09-27
- Модули: core:secrets:{api,impl}, core:datastore:{api,impl}, platform-main:di-bundle

## Контекст

API-ключи, токены и персональные данные требуют защищённого хранения. Один ключ может использоваться
несколькими движками; ротация должна менять единственное значение, удаление — учитывать все использования.
Смена профиля закрывает доступ, но не удаляет его данные.

## Решение

SecretStore привязан к ProfileScope. SecretKey — стабильный технический ID в пространстве профиля.
SecretUsage(type, id, slot) — постоянная ссылка потребителя; имена движков и UI-метаданные остаются у владельца.
Движки не владеют копиями ключей и разрешают ссылку при открытии сессии.

На профиль сохраняется один защищённый снимок: версия формата, map значений и список ссылок.
Транзакция bind проверяет существование ключа; remove проверяет ссылки и возвращает InUse с их списком.
write заменяет значение без смены ключа. Снимок выбран для атомарности значения и ссылок, без двухфазной
записи в обычную БД и защищённое хранилище. Это рассчитано на небольшой vault учётных данных/персональных полей,
не на документы и историю чатов.

Android использует AES-256-GCM (случайный IV при каждой записи), ключ в Android Keystore, профиль в AAD,
AtomicFile в noBackupFilesDir. Windows — DPAPI CurrentUser с профильным entropy, запись ciphertext
во временный файл и атомарная замена. Apple — Keychain generic-password, SecItemUpdate либо SecItemAdd;
На iOS — AfterFirstUnlockThisDeviceOnly; на macOS — Login Keychain с системными ACL и блокировкой, без iCloud sync. Профиль в пути/account — SHA-256 его UTF-8 ID.
Хеш — разделение имён, не механизм шифрования или анонимизации легко угадываемых ID.

Добавляется net.java.dev.jna:jna-platform 5.19.1 только для JVM: прямые вызовы DPAPI/Security/CoreFoundation,
без CLI-процессов и без секретов в argv. Координаты — version catalog.
[Исходники и релизы JNA](https://github.com/java-native-access/jna),
[DPAPI wrapper](https://github.com/java-native-access/jna/blob/master/contrib/platform/src/com/sun/jna/platform/win32/Crypt32Util.java),
[Android Keystore](https://developer.android.com/privacy-and-security/keystore),
[доступность Keychain](https://developer.apple.com/documentation/security/ksecattraccessibleafterfirstunlockthisdeviceonly).

Внутри AppScope операции сериализованы Mutex, на платформе — блокировкой стабильного файла профиля,
который не заменяется вместе с ciphertext. На JVM вторая одновременная блокировка из другого графа может
быть отклонена FileChannel; ошибка выходит вызывающему, обновление не затирается.
Внешние процессы обязаны использовать тот же протокол блокировки.

ProfileStorageCleaner — app-scoped multibinding расширения явного StorageMaintenance.wipeProfile.
StoreRegistry вызывает участников внутри своего wiping gate, до удаления обычных файлов.
SecretStore инжектирует профильный DataStores, тем самым регистрирует профиль в этом же gate.
Wipe не читает/дешифрует снимок и работает даже при повреждении или потере ключа Android Keystore.
Он игнорирует ссылки, поскольку удаляется весь профиль. Смена/закрытие профиля wipe не вызывает.

## Безопасность и границы

Secret владеет CharArray, toString скрыт, reveal очищает временный массив в finally; close очищает свой.
Отменённое чтение очищает недоставленный Secret. Это best effort: JSON сериализация создаёт временные строки,
и runtime/транспорт могут делать неочищаемые копии до GC. Нет обещания защиты памяти от отладчика,
скомпрометированного процесса, root или вредоносного кода под текущим пользователем.

На диске нет открытых значений, справочника ссылок или метаданных потребителей. Только ciphertext/Keychain,
технические SHA-256 имена и пустые lock-файлы. OS backup/snapshot может сохранять прошлую версию;
физическое стирание накопителя не обещается. Android/iOS требуют повторного ввода ключей после переноса; desktop backup/migration подчиняется политике ОС.

SEC пишет только название операции. Ошибки нативного backend/JSON заменяются диагностикой класса ошибки
без message/cause/suppressed исходного исключения. Повреждение не трактуется как пустой vault и не перезаписывается.
CancellationException пробрасывается.

Хранение ссылок защищает зарегистрированных потребителей. Интеграция движков должна регистрировать слот до
сохранения конфигурации, читать через readFor и освобождать слот после удаления конфигурации.
Сбой между этими шагами может оставить лишнюю ссылку; восстановление/сверка — ответственность владельца конфигурации.
Уже прочитанные ключи не меняются задним числом; новые сессии увидят замену, старым нужен перезапуск.

Модуль инфраструктурный, без самостоятельного UI и feature toggle: включение экрана/движка будет защищено
тоглом соответствующей фичи. Отключение тогла не должно удалять секреты или обходить защиту.
Linux не входит в целевые платформы: обращение завершается ошибкой, незашифрованного fallback нет.

## Проверка

Common-тесты проверяют буферы Secret, ротацию для двух потребителей, запрет удаления, rebind,
переключение профиля/новый registry, ошибки/отмену и повреждение. Native JVM тест проверяет реальный backend,
повторное открытие и удаление повреждённого DPAPI blob. Интеграционные тесты проверяют DI, общий wipe gate
и сохранность после переключения. iOS-компиляция проверяется Gradle, линковка и исполнение требуют macOS; Android runtime требует устройства.

На macOS не задаём kSecAttrAccessible: Apple разрешает этот атрибут только для Data Protection Keychain
или синхронизируемых записей. Desktop использует обычный Login Keychain, доступный приложению без
добавления entitlements в этом PR. См. [kSecAttrAccessible](https://developer.apple.com/documentation/security/ksecattraccessible).
