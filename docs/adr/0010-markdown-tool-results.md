# ADR-0010: Markdown и результаты инструментов в чате

Статус: принято. Дата: 2026-09-26.

## Контекст

Ответ агента поступает постепенно и может содержать Markdown, незакрытые code fences,
таблицы и длинный вывод инструментов. Собственный парсер на регулярных выражениях не даёт
надёжной совместимости с вложенной разметкой, экранированием и GFM. Огромный Compose Column
для всего ответа создаёт слишком много элементов и мешает прокрутке.

## Решение

Добавлена зависимость `org.jetbrains:markdown:0.7.9` в `design-system:components` через
version catalog. Это [KMP-парсер JetBrains](https://github.com/JetBrains/markdown) под Apache-2.0;
официальная сборка публикует JVM и iOS-артефакты. Используется GFM flavour и дерево AST,
а не HTML-рендерер. Парсер скрыт за API `parseHbMarkdown` и не входит в публичные модели.

Модель `HbMarkdownBlock` содержит семантический тип, текст и независимые от темы spans.
Большие блоки разбиваются по 2048 UTF-16 символов или 24 строкам с сохранением spans
и границ surrogate pairs. Идентификаторы основаны на исходной позиции и номере части:
дописанный ответ не меняет ключи завершённых блоков. Transcript подготавливает изменённое
сообщение один раз и размещает блоки в общем lazy list. Standalone-компонент ограничивает
высоту и использует собственный lazy viewport.

Вызовы инструментов описываются `HbToolCall` и типизированными `HbToolBlock`:
Markdown, Console, Diff. У вызова стабильный id, заголовок, краткое описание и статус.
В основном transcript раскрытие хранится в `HbToolExpansionState`, независимо от
скомпонованных строк. Подробности включаются отдельными интервалами в общий `LazyColumn`:
вложенной вертикальной прокрутки у инструмента нет. Индекс tool key → базовая позиция
обновляется только при изменении сообщения, поэтому раскрытие не копирует всю историю.
Подготовленные payload-строки переиспользуются, пока blocks не меняются. Размеры chunks
те же, что у Markdown. Код прокручивается горизонтально, строки diff сохраняют символы
`+` и `-`, а также получают семантический фон. Статусы и действия локализуются через
`HbToolLabels`.

Standalone `HbToolCallView` сохраняет controlled/uncontrolled disclosure и выводит
обычный Column без собственной вертикальной прокрутки. Он предназначен для небольших
результатов; большие результаты следует передавать в `HbChatTimeline`, где они
виртуализируются вместе с сообщениями.

HTML отображается как текст. Изображения не загружаются. Ссылки инертны без явно переданного
обработчика `onLinkClick`; допускаются HTTP(S), mailto, якоря и пути. Renderer никогда сам
не открывает браузер. Логи действий содержат только идентификаторы, без URL и payload.

## Последствия

Новая зависимость добавляет один проверенный KMP-парсер вместо собственной реализации
грамматики. Сохраняется ответственность проекта за Compose-рендерер, темизацию и виртуализацию.
Code fences получают моноширинное оформление и подпись языка; подсветка синтаксиса языков
не включена. Таблицы представлены отдельными строками с горизонтальной прокруткой.
Streaming повторно парсит изменённое сообщение; остальные сообщения и завершённые равные
блоки переиспользуются на уровне timeline. Остановка генерации сохраняет незавершённый Markdown.

Проверки: common tests на вложенные стили, таблицы, списки, неполные fences, безопасные
ссылки, большие блоки и diff; UI tests на контролируемое раскрытие и восстановление состояния
после ухода tool call из lazy viewport. iOS-компиляция выполняется отдельно на macOS.
