# Политика PR и коммитов

PR содержит законченную фичу. Коммиты внутри PR образуют последовательность логических шагов
для ревью: контракт, реализация с тестами, интеграция, UI. Каждый коммит оставляет проект
собираемым; тесты изменённого поведения добавляются вместе с реализацией. Перед ревью
промежуточные `fixup` объединяются с соответствующим шагом. Общего лимита размера PR нет.

## Бюджет одного коммита

| Метрика | Правило |
|---|---|
| Токены полного diff | **≤25 000**; превышение блокирует проверку |
| Предупреждение по токенам | **>20 000** |
| Предупреждение по файлам | **>20**; само по себе не блокирует проверку |
| Добавленные + удалённые строки | Ориентир **700–1000**, без жёсткого ограничения |

Бюджет получен из выбранной базы: 250 000 × 10% = 25 000 токенов.
Доля 10% — договорённость о расходе контекста, а не гарантия качества ревью.
Превышающий бюджет логический шаг нужно разделить на собираемые коммиты внутри того же PR.

## Как считается объём

- Проверяется **каждый коммит**, а не итоговый diff PR. Отмена большого изменения следующим
  коммитом не отменяет проверку первого. Коммиты, уже входящие в целевую ветку, не проверяются повторно.
- Обычный коммит сравнивается с его родителем, корневой — с пустым деревом,
  merge-коммит — с первым родителем. Merge не пропускается: в его бюджет попадают и изменения,
  принесённые второй веткой. Если они велики, обновляй ветку через rebase и повторяй проверку.
- Считается текст Git diff: добавления, удаления, три строки окружающего контекста с каждой
  стороны, пути и заголовки. Формат фиксирован скриптом: Myers, без indent heuristic,
  полный индекс объектов, распознавание переименований с порогом 50%, без textconv/external diff.
- Метрика: `max(tokens_o200k_base(diff), tokens_cl100k_base(diff))`, `tiktoken==0.14.0`.
  Это воспроизводимая метрика проекта, а не обещание точного размера запроса любой модели.
- Тесты, документация, конфигурация, отслеживаемые генерируемые и lock-файлы входят в бюджет:
  их текст тоже занимает контекст. Автоматических исключений по путям нет.
- Чистое переименование учитывается как один файл и небольшой diff метаданных.
  Бинарные файлы учитываются в числе файлов и текстовых метаданных diff; содержимое изображений,
  архивов и других бинарных файлов этой метрикой не измеряется и проверяется отдельно.
- Полные затронутые файлы и зависимости, дополнительно прочитанные ревьюером, в этот бюджет
  не входят. Если они включены в запрос к модели, их токены нужно учитывать дополнительно.

## Локальная проверка

Нужны Git ≥2.31 и Python ≥3.12. Из корня репозитория:

```bash
python -m pip install -r scripts/requirements-commit-policy.txt
python scripts/check_commit_size.py --staged
python scripts/check_commit_size.py --commit HEAD
python scripts/check_commit_size.py --base origin/master --head HEAD
python -m unittest discover -s scripts/tests -v
```

`--staged` читает только индекс Git. Неподготовленные изменения и untracked-файлы не входят
в будущий коммит и в этот расчёт. `--base` проверяет диапазон `base..head`; вместо
`origin/master` указывай фактическую целевую ветку PR после её обновления через `git fetch`.
Для проверки диапазона нужна полная история Git. Коды завершения: `0` — пройдено
(возможны предупреждения), `1` — превышение бюджета, `2` — проверка не выполнена из-за ошибки.

Подсчёт выполняется локально. API-ключ не нужен, код никуда не отправляется.
При первом запуске `tiktoken` загружает публичные словари токенизаторов и затем использует кэш.
Если зависимость или словари недоступны, проверка завершается ошибкой, без оценки по символам.

## CI

Workflow [Commit policy](../../.github/workflows/commit-policy.yml) запускается для PR,
проверяет сам инструмент тестами и затем каждый коммит между SHA целевой ветки и SHA ветки PR.
Результаты выводятся по коммитам в лог и сводку GitHub Actions. Проверка не компилирует каждый
коммит: собираемость и смысловая связность остаются обязательствами автора и ревьюера.

После публикации workflow статус **Commit size** нужно сделать обязательным в ruleset/branch
protection целевой ветки GitHub. Наличие workflow само по себе не запрещает merge красного PR.
Локальная команда не устанавливает Git hooks и не меняет настройки GitHub.

Основание выбора инструмента — [ADR-0016](../adr/0016-commit-review-budget.md).
