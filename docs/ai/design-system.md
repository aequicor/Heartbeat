# Aequicor Glass UI — пастельное стекло

Актуальный стиль по прямому запросу пользователя — **glassmorphism**:
полупрозрачные поверхности, тонкие светлые контуры, мягкие внешние тени и blur
перекрывающих панелей ([ADR-0011](../adr/0011-glass-surfaces.md)). Пастельная палитра
из [ADR-0009](../adr/0009-pastel-neumorphism.md) сохраняется в light/dark.

Последнее уточнение пользователя задаёт **компактный минимализм**: небольшие шрифты,
короткие интервалы, спокойная навигация и основной акцент на содержимом. Крупные
маркетинговые hero-блоки убраны; стеклянный фон остаётся сдержанным. Это уточнение
оформления при неизменном графе модулей и наборе возможностей.

## Кинематографичный welcome

Welcome — отдельная светлая композиция по [ADR-0013](../adr/0013-welcome-and-local-flags.md).
`HbTheme.welcome` задаёт собственные размеры, типографику и тайминги: 6 секунд,
заголовок 48 sp (32 sp на компактном экране), центральный блок до 960 dp,
кнопки минимум 48 dp по высоте. Общая `HbTypography` рабочих экранов не меняется.
`HbCinematicBackdrop` и `HbGlassOrbit` рисуют сцену на Canvas, читают прогресс в draw-фазе
и не запускают свои анимации. Владелец останавливает прогресс на финальном кадре;
пропуск и reduced motion сразу показывают финал. Пример с повтором есть в Components-каталоге.
`HbSwitch` использует Foundation, единые токены и семантику Switch во всех UI-китах.

## Плотность и типографика

### Иконки

`HbIcons` и `HbIcon` из `design-system:components` задают общий векторный стиль для всех
платформ: сетка 20×20, контур 1.4 единицы, скруглённые окончания и соединения линий.
Размеры — `HbDimensions.iconSize` (18 dp) для навигации и действий и `iconSmallSize`
(14 dp) для метаданных. Обычные иконки используют `textSecondary`, активные —
`textPrimary`; `HomeFilled` обозначает выбранный домашний раздел. Иконка внутри
кнопки не уменьшает её область нажатия. Декоративные иконки имеют
`contentDescription = null`, название действия остаётся у родительского контрола.
Геометрия не зависит от шрифта; стрелки назад/вперёд, боковая панель и шеврон
раскрытия зеркалируются для RTL; также зеркалируются Undo, Redo, Reply и Send.

В отдельном разделе **Иконки** sandbox — 110 векторов: навигация, действия,
файлы и контент, общение, статусы, рабочая среда и медиа. Поиск по API-имени
не учитывает регистр и сочетается с фильтром категории. Результат объявляется
скринридеру. Каждая иконка показана в 14/18/24 dp; крупный размер задаёт
`HbDimensions.iconLargeSize`. `HbIcons.All` — неизменяемый полный список.
Внизу сохранены активное состояние и компактная строка проекта/окружения/ветки.

[Увеличенный рендер полного набора](previews/icons.png) генерирует JVM-тест
`HbIconGeometryTest`. Он проверяет запас под контур у всех иконок, симметрию
основных знаков и отражение направленных иконок для RTL. Шестерёнка имеет
восемь равномерных зубцов, Wi-Fi — концентрические дуги; точки обоих меню
используют одинаковую заливку и радиус.

`HbComposerMenuButton(icon = HbIcons.Plus, ...)` отображает векторный триггер.
Параметр `isIcon` оставлен для совместимости с пользовательскими текстовыми глифами.

### Иллюстрации

`HbIllustration(illustration = HbIllustrationKind.EmptyWorkspace, contentDescription = null)`
отображает оригинальную векторную сцену 240×180. Набор: Welcome, EmptyWorkspace,
EmptyChat, NoResults, Success, Error, Offline, Upload. Цвета берутся из текущей темы;
успех и ошибка используют семантические акценты. Вектор кешируется по сцене и палитре,
масштабируется с сохранением пропорций и одинаково работает во всех платформенных китах.
Стандартные размеры — `illustrationWidth` / `illustrationHeight`; можно передать
свой `Modifier.size(...)`.

Текст состояния и действия принадлежат экрану, а не иллюстрации. Если рядом есть
описание, передавай `contentDescription = null`; иначе — локализованное описание.
Иллюстрации статичны и не требуют разрешения на анимацию. Отдельный раздел
**Иллюстрации** в sandbox показывает все восемь сцен с RU/EN подписями и именами API.
[Превью светлой темы](previews/illustrations.png) получено из `AssetCatalogUiTest`.
Оба раздела доступны из боковой и компактной навигации, поддерживают светлую/тёмную
тему и общие auto-hide scrollbars. Каталожные примеры не меняют поведение приложения
и не требуют feature toggle; включение сцен в будущих фичах контролируется их тоглами.

### Текст и интервалы

| Токен (`HbTypography`) | Размер / высота строки, sp |
|---|---|
| `display` | 22 / 28 |
| `title` | 17 / 23 |
| `body` | 14 / 20 |
| `label` | 13 / 18 |
| `caption` | 11 / 16 |
| `code` | 13 / 19 |

`HbSpacing`: `xxs/xs/s/m/l/xl/xxl` = **2/4/6/8/12/16/20 dp**.
`HbShapes`: `small/medium/large` = **6/10/14 dp**. Боковая панель — 192 dp;
composer — минимум 56 dp, редактор — минимум 40 dp, максимальная высота — 120 dp.

В transcript внешние поля списка и внутренние поля сообщения — `l` (12 dp).
После поверхности заголовка секции — `m` (8 dp), между сообщениями — `l` (12 dp),
между блоками Markdown — `s` (6 dp). Интервал задаётся один раз: продолжения
lazy-сегментов не добавляют верхний отступ, последний элемент не дублирует нижнее
поле списка. Сегменты одной консоли или diff соединяются без зазоров.
При горизонтальном переполнении код резервирует `m` (8 dp) под scrollbar;
без переполнения этот резерв не добавляется.

Функциональные области разделяются `HbPanel` (заливка `glassTint`, граница
`outlineSubtle`) и `HbDivider`, без наращивания отступов или размеров шрифта.
Навигация имеет собственную область, действия диалога объединены с историей в одну
панель, ввод расположен отдельно. Границы нужны между разными функциями; абзацы
одного ответа не превращаются в отдельные карточки. Заголовки секций инструмента
отделяют подробности, консоль и изменения кода. Панели не добавляют blur на каждую
строку, не обрезают тени и не владеют прокруткой.

Платформенная плотность выбирается в `HbTheme` через `defaultHbDimensions()`.
На JVM `touchTarget` получает значение `controlHeight` — **32 dp**; на Android и iOS
область нажатия сохраняет **48 dp**. Выбор Material, Fluent или macOS-кита не меняет
эту настройку: она зависит от платформы, а не от выбранного внешнего вида контролов.

## Платформенные киты

Основной режим `HbVisualStyle.Glass` использует общие Foundation-компоненты и Haze.
`Neumorphic` сохранён для совместимости. В `HbVisualStyle.Platform` используются киты ниже.

| Платформа | Реализация `Hb*` | Библиотека |
|---|---|---|
| Android, iOS | Material 3, перекрашенный токенами | `org.jetbrains.compose.material3` |
| Windows | Fluent Design | https://github.com/compose-fluent/compose-fluent-ui |
| macOS | macOS 26 (Liquid Glass) | https://github.com/NucleusFramework/compose-macos-26-ui |

- Desktop — один JVM-таргет, поэтому кит выбирается **в рантайме** (`os.name`) и прокидывается через `LocalPlatformUi`.
- Пастельные токены мапятся на цветовые схемы Fluent/macOS (accent = `brand`).
- Фичи не импортируют классы китов напрямую — только `Hb*`.

## Правила для фич

- Только `HbTheme.colors.*`, `HbTheme.typography.*`, `HbTheme.spacing.*`.
- Никаких `Color(0x…)`, `Color.Red`, литералов `16.dp`/`14.sp` для стилей (размеры layout'а через `HbTheme.spacing`).
- Любой `@Composable` экран принимает `modifier: Modifier = Modifier` первым опциональным параметром (compose-rules).
- Превью — в `impl` (`@Preview` с `HbTheme` в light и dark).
- Строки — только из Compose Resources (`core:resources` или ресурсы модуля фичи), не хардкод.

`HbShadows`: внешние тени имеют размытие 12 dp и смещение 6 dp; вогнутые/нажатые —
4 dp и 2 dp. Светлая тень направлена вверх влево, тёмная — вниз вправо; эти токены

формам, elevation, размерам и параметрам движения.

## Чат

`HbChatMessage` содержит ID, автора, текст, роль, вид, статус и `HbMessageAppearance`.
Текст очередного фрагмента заменяет модель с тем же ID. Представление независимо
настраивает тон, foreground/background, долю ширины и start/center/end.
Обычный нейтральный ответ ассистента выводится на непрозрачной `assistantSurface`:
белой в светлой теме и приподнятой тёмной в dark. Поверхность единая для текста,
Markdown и инструментов, включая виртуализированные блоки длинного ответа;
без дополнительных теней и рамок. Явно заданный фон, семантический тон и ошибки
сохраняют своё оформление.
`HbChatTranscript` виртуализирует сообщения, принимает собственный рендер через слот
и сохраняет положение чтения истории. `HbChatComposer` принимает значение и события
извне; отправка и остановка генерации принадлежат вызывающему коду.

Для длинных сессий используется overload с `HbChatTimeline`: история готовится один раз,
`replaceLatest` меняет только хвост, `prepend` добавляет предыдущую страницу без смены
ключей видимых строк. `HbChatSection` создаёт настоящий sticky header. Длинный текст и
Markdown разбиваются на строки одного lazy-списка, семантическая поверхность сообщения
остаётся непрерывной. На границах viewport действует плавное затухание.

`HbStickyHeaderHost` разделяет прокручиваемый слой и закреплённый заголовок:
native sticky slot задаёт размер и вытеснение следующей секцией, а поверхность
закреплённого заголовка рисуется поверх списка. Маска затухания строк не должна
затрагивать контур и внешнюю тень этой поверхности. Один host используется в чате
и примере списка каталога.

`HbMessageKind.Markdown` поддерживает заголовки, списки/задачи, цитаты, таблицы, ссылки
и fenced code. `toolCalls` содержит раскрываемые результаты с Markdown, буквальным
выводом консоли и unified diff. Их фрагменты включаются в общий lazy-список без вложенной
вертикальной прокрутки. `HbToolExpansionState` сохраняет раскрытие при lazy disposal,
а индекс инструментов и подготовленные строки обновляются только для изменённого сообщения.
HTML не исполняется, изображения не загружаются;
переход по ссылке выполняется только через callback владельца.

Код с указанным языком подсвечивает ключевые слова, строки, числа, комментарии,
типы, вызовы и аннотации. Поддерживаются Kotlin, Java, JavaScript/TypeScript, JSON,
Python и shell (включая короткие имена `kt`, `js`, `ts`, `py`, `sh`). Неизвестный
язык и блок без языка сохраняются обычным текстом. Для `HbMessageKind.Code` язык
задаётся через `codeLanguage`, для Markdown — после открывающего fence.
Лексические диапазоны готовятся до разбиения на lazy-блоки: многострочные строки
и комментарии не теряют цвет на границах. Смена темы меняет только палитру.
Это лексическая подсветка, без семантического анализа типов, JSX, shell heredoc
и отдельного разбора выражений внутри строк. Консоль остаётся буквальным выводом,
diff сохраняет цвета добавленных/удалённых строк.

Вывод консоли расположен на отдельной графитовой поверхности в обеих темах.
Подсветка строк распознаёт префиксы команд, `> Task`, уровни логов, результат сборки
и `exit code`. Обычный текст сохраняет основной цвет; управляющие ANSI-последовательности
не исполняются и не декодируются. Подготовленные диапазоны продолжаются через lazy-блоки.
Фон неподвижен при горизонтальной прокрутке, между сегментами нет светлых зазоров,
скруглены только внешние края панели. Горизонтальная полоса использует `consoleMuted`.

`HbDiffView` оформляет unified diff отдельной панелью с заголовком для каждого файла.
В заголовке — выделяемый путь и компактная кнопка копирования полного пути через
системный clipboard. Подтверждение и ошибка объявляются через live region; время
обратной связи задаёт `HbMotion.copyFeedbackMillis`. Пути не записываются в логи.
Цвета строк используют существующие семантические контейнеры, основной фон —
`assistantSurface`, заголовок — `surfaceElevated`. Общий Foundation-компонент одинаков
для Material, Fluent и macOS. В transcript используются подготовленные lazy-сегменты
без дополнительной вертикальной прокрутки; длинные строки имеют auto-hide scrollbar.

Composer — цельный многострочный редактор с нижней панелью. `leadingContent` и
`trailingContent` принимают действия, `HbComposerMenuButton` — управляемое меню
с Escape, стрелками, Tab и восстановлением фокуса. `HbGlassPanel` отделяет фон blur
от переднего содержимого: скругление фона не обрезает внешние тени дочерних элементов.

Контракты и пример — [components/README.md](../../design-system/components/README.md).
Стриминг агента, хранилище истории и state-machine реализуются будущей фичей `api/impl`.

## Полосы прокрутки

Каждая прокручиваемая поверхность по обеим осям использует общие auto-hide scrollbar
из `layouts`: `hbHorizontalScroll`, `hbVerticalScroll`, либо `hbScrollbars` для уже
существующего состояния. `HbLazyColumn`/`HbLazyRow` включают полосу автоматически.
Она скрыта в покое, появляется при прокрутке и наведении на её область, поддерживает
drag и нажатие на track. Появление не меняет доступное место содержимого.

Обычные поверхности используют реальный диапазон `ScrollState`. Lazy-списки используют
логические единицы элементов и фиксированный масштаб размера thumb: измерение новых
строк разной высоты не меняет его длину. Положение учитывает частично видимые строки.
При изменении количества элементов или размера окна геометрия может обновиться.
Полоса sticky host находится вне слоя затухания; внутренний lazy list отключает свою
через `showScrollbar = false`. Ввод также имеет полосу: общий Foundation-редактор
используется для `HbTextField` во всех стилях и для composer. Обоснование и границы
платформенного fallback — [ADR-0012](../adr/0012-scrollbars.md).
