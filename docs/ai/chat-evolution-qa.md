# Chat и Glass UI: проверка 26.09.2026

Ветка: `codex/design-system-uikit-sandbox`. Проверяется локальная демонстрационная
app, без сетевого провайдера и выполнения показанных в сообщениях команд.

## Реализовано

- Единый многострочный composer с меню над полем, выбором режима и профиля локального
  ответа, отправкой / остановкой. Enter переносит строку, Ctrl/Cmd+Enter отправляет.
- Стеклянные поверхности, пастельный фон, blur под перекрывающими панелями,
  внешние тени и прозрачные градиентные маски на краях прокрутки.
- Настоящие sticky headers в transcript и отдельном примере Layouts.
- Markdown: заголовки, вложенные стили, обычные и task-списки, цитаты, таблицы, ссылки и code fences,
  включая незавершённую разметку при потоке. Языковая подсветка синтаксиса не включена.
- Раскрываемые tool calls с локализованными секциями Markdown, Console и Diff,
  статусами, сохранением раскрытия и виртуализацией вывода в общем lazy-списке чата.
- Persistent timeline, стабильные ключи и content types, страницы истории, ленивые
  фрагменты больших сообщений. Изменение потока не пересоздаёт всю историю.

## Исправление обрыва тени закреплённого заголовка

По скриншоту пользователя воспроизведён горизонтальный обрыв нижней тени в тёмной
теме. Причина: `DstIn`-маска применялась к уже собранному списку вместе с заголовком
и стирала его тень ниже границы строки.

`HbStickyHeaderHost` теперь рисует закреплённую поверхность отдельным слоем.
Native sticky slot сохраняет измерение и push-off; его скрытая копия не размещается
и не дублирует pointer input или доступный заголовок. Haze получает строки до
маскирования, а маска действует только на отображение списка. Во время вытеснения
уходящий заголовок плавно теряет непрозрачность, сохраняя внешнюю тень. Решение
подключено к transcript и bounded list в Layouts.

Добавлены четыре регрессионных теста: пиксельное сравнение скруглений и тени с тем
же заголовком вне списка в светлой/тёмной темах; одинаковое расстояние прокрутки
при одинаковом вводе колеса над заголовком и над строками; замена/очистка истории
с ранее закреплённой секцией. Последний закрывает обращение к устаревшему ключу
между обновлением timeline и следующим измерением LazyColumn.

Итог этого прохода: **73 теста components + catalog, 0 failures/errors**. Общий
Detekt, typed-анализ этих модулей, Android APK и Windows distribution прошли.
Лог: `build/sticky-shadow-final.log`. Пиксельные сравнения:
`design-system/components/build/previews/sticky-header-light.png` и
`sticky-header-dark.png` (слева список, справа контрольный компонент).

Computer-use в Windows подтвердил непрерывную тень в обеих темах, смену секций,
сброс истории с закреплённой старой секцией и bounded list каталога. Дополнительно
найден и исправлен слишком маленький шаг колеса над заголовком: desktop Compose
вычисляет его по высоте scrollable-узла. Обработка перенесена на общий контейнер
размером с viewport; равенство шага закреплено тестом и проверено в финальном EXE.

## Единая прокрутка результатов инструментов

Вертикальный viewport внутри tool call удалён. Раскрытые Markdown, Console и Diff
вставляются отдельными lazy-интервалами после заголовка инструмента в тот же список,
который показывает сообщения. Горизонтальная прокрутка длинных строк кода сохранена.
Standalone tool view использует обычный Column; большие результаты следует передавать
в timeline, где они виртуализируются по частям.

Индекс инструментов обновляется при append/replaceLatest/prepend без копирования всей
истории. Подготовленные строки переиспользуются при неизменных blocks. Состояние
раскрытия хранится выше lazy items в `HbToolExpansionState`. Итоговый индекс для
следования потоку учитывает раскрытые строки; само раскрытие не тянет читателя вниз.

Нагрузочная проверка: 12 000 строк консоли + 12 000 строк diff, более 900 внешних lazy
items, ограниченное число скомпонованных строк до/после глубокого перехода. Проверены
колесо над выводом, lazy disposal, stream/prepend, восстановленная позиция внутри
payload и сворачивание большого результата выше viewport. Последний сценарий выявил
ограничение ближайшего кеша ключей Compose: теперь позиция явно переносится по ключу
и смещению через интервалы до следующего измерения. Также устранены коллизии ключей
при ID блока, содержащем двоеточие.

Итог: **83 теста components + catalog, 0 failures/errors**; общий Detekt и typed-анализ,
Android APK и Windows distribution — успешно. Лог: `build/inline-tools-final.log`.
Computer-use подтвердил, что колесо над выводом двигает весь чат, полный diff доступен,
раскрытие/сворачивание и светлая/тёмная темы работают. Это проверки виртуализации и
поведения; инструментальные замеры FPS и памяти не проводились.

## Общие полосы прокрутки (2026-09-27)

В `layouts` добавлены общие полосы для обеих осей. `HbLazyColumn`/`HbLazyRow` включают
их по умолчанию, обычные поверхности используют `hbHorizontalScroll`/`hbVerticalScroll`.
Вся прокрутка DS и каталога переведена на эти обёртки; редакторы используют собственный
hoisted `ScrollState`. Полоса находится поверх содержимого, но вне fade sticky host.
В поле ввода она рисуется в существующем отступе, без увеличения высоты поля.

Размер thumb lazy-списка не зависит от измеренных высот видимых строк. Позиция
нормализуется по логическим координатам элементов; промежутки и padding учитываются
отдельно. Уходящий sticky header исключается и при вытеснении в верхний padding.
Seek мышью уточняет позицию ограниченным поиском, чтобы после release не было скачка.
Без переполнения полоса не рисуется и не перехватывает ввод. Touch сохраняет обычный
swipe; захват thumb выполняется только основной кнопкой мыши.

Итог: **119 тестов, 0 failures/errors**: tokens — 5, layouts — 10, components — 84,
catalog — 20. Проверены hover/fade в обеих темах, wheel, drag/release и края диапазона,
RTL/reverse, touch у края, высокая/низкая строка с шагом 1 px, spacing/padding, pinned
и вытесняемый header, а также controlled editor, курсор, выделение, очистка и Undo/Redo.
Общий Detekt, typed-анализ layouts/components/catalog, Android APK и Windows
distribution прошли. Логи: `build/scrollbars-regression-final.log`,
`build/scrollbars-padding-final.log`; метрики — `build/scrollbars-layout-check.log`
(первый typed-проход имел исправленные naming/signature замечания; итоговый layouts
typed-анализ прошёл в `build/scrollbars-final.log`).

Computer-use в готовом Windows EXE подтвердил hover, исчезновение в покое, колесо,
переход ползунком в середину истории из 10 000 сообщений без сдвига после release,
светлую/тёмную темы и горизонтальное перетаскивание однострочного редактора. Визуальная
проверка выявила наложение полосы на текст поля: scrollbar перенесён наружу от его
внутреннего padding, поле сохранило прежнюю высоту. Это проверки поведения и
виртуализации; FPS и расход памяти инструментально не измерялись.
