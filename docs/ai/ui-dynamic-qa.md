# Динамическая проверка UIKit Sandbox

Дата: 26.09.2026. Платформа: Windows, Desktop JVM 21.

Применены проектный скилл `design-system`, UI-reviewer, `make-interfaces-feel-better`,
`accessibility` и Windows `computer-use` (`@oai/sky`). Проверяется реальный собранный
Desktop sandbox; изолированные Compose UI-тесты дополнительно фиксируют промежуточные
кадры hover/press и управляют временем анимации.

## Найденные дефекты

| Проверка | До исправления | Исправление |
|---|---|---|
| Запуск упакованного EXE | Computer-use показал `Failed to launch JVM`; stack trace выявил конфликт главного потока Lifecycle | Убрана транзитивная Tao-диспетчеризация из macOS-кита: у нашего AWT-хоста остаётся Swing `Dispatchers.Main`. В runtime также включены `java.instrument`, `jdk.unsupported` из `suggestModules` |
| Наведение на Soft UI | Кнопки и вкладки визуально не реагировали на hover | Отдельный пастельный overlay, плавный переход; без изменения размера |
| Нажатие и отпускание | Рельеф переключался мгновенно | Перенаправляемая анимация цвета и теней; стабильный состав модификаторов |
| Переключение темы и варианта кнопки | Цвет текста обновлялся раньше анимируемой заливки; в живом окне была видна вспышка, для Primary ↔ Quiet расчётный контраст падал до 1.49–1.75:1 | Текст и фон одновременно принимают новую палитру/вариант; hover и press продолжают анимироваться, фокус сохраняется |
| Поле с введённым текстом | Назначение было задано только исчезающим placeholder | Постоянная accessibility-подпись |

| Статус генерации | Верхний badge оставался Ready при видимой кнопке Stop | Working во время потока, Ready после завершения/отмены; polite live region |

## Проверка результата

### Computer-use: реальный Windows EXE

- Упакованное приложение запускается после исправления диспетчера главного потока.
- Наведение на вторичную Soft UI-кнопку меняет заливку; уход указателя возвращает
  обычное состояние. Проверено в светлой и тёмной темах. Во Fluent также виден hover.
- Клик по «Создать» показывает «Действие принято». Disabled-кнопка не выполняет
  действие. Tab показывает обводку фокуса и пропускает disabled-кнопку.
- Ввод кириллицы работает; текст сохраняется при смене темы и Soft UI / Native UI.
- После исправления смена светлой и тёмной палитры отображает согласованные фон
  и текст уже в первом захваченном кадре. Точный первый Compose-кадр дополнительно
  проверяется тестом с остановленными часами.
- Клик «Лаванда» меняет выделение выбора и фон ответа; «Полная» меняет ширину
  и переносы текста. Переключение выделения в тёмной теме не даёт вспышки подписи.
- Ctrl+Enter отправляет локальный запрос, очищает поле и запускает поток. Видны
  частичный ответ, «В работе», кнопка «Остановить» и автопрокрутка к ответу.
  После завершения возвращается «Готово». Отмена до завершения подтверждена
  детерминированным UI-тестом: при попытке computer-use поток успел закончиться.

### Детерминированные Compose UI-тесты

Проверены hover → выход, удержание → отпускание, отмена нажатия уходом указателя,
disabled, Tab / Enter / Space, перенаправление незавершённой анимации, reduced motion,
постоянная accessibility-подпись поля и контраст первого кадра при смене палитры
и Primary ↔ Quiet / Secondary.
Отдельные сценарии проверяют навигацию, отправку/отмену потока, чтение истории без
принудительной прокрутки вниз и переход к последнему сообщению.

Артефакты реального Compose-рендера: `design-system/components/build/previews/interaction-*.png`
и `design-system/catalog/build/previews/`. Это кадры тестового рендера, не скриншоты
окна computer-use.

Итог: **47 тестов, 0 ошибок, 0 пропусков** — tokens (4), resources (2), adaptive (4),
components (22), catalog (14), desktop (1). Desktop `createDistributable` и Android
`assembleDebug` проходят. Общий Detekt и анализ с типами для tokens, theme, resources,
layouts, components, catalog и desktop проходят. После последних изменений повторены
сборки Desktop/Android, тесты components/catalog и оба вида Detekt этих модулей.
Логи: `build/uikit-dynamic-final.log`, `build/uikit-dynamic-recheck.log`.
Первый прогон выявил ошибку синхронизации нового теста локали; она исправлена,
повторный прогон завершился `BUILD SUCCESSFUL`.

### Границы проверки

- Удержание кнопки и промежуточные кадры проверены Compose input API: computer-use
  возвращает управление после полного клика.
- Компактная ширина 390 и широкое низкое окно 900 × 500 проверены в Compose UI-тестах.
  Изменение размера реального окна через computer-use не удалось подтвердить.
- Windows UI Automation видит контейнер окна, но не отдельные Compose-контролы.
  Работа экранного диктора не подтверждена; семантика проверена внутри Compose.
- iOS и macOS не запускались на этом Windows-хосте. Android проверен сборкой APK.
- Известное ограничение анализа с типами `adaptive:detektMainJvm` описано
  в [README sandbox](../../platform-main/uikit-sandbox/README.md).
