# Тестирование и приёмка фичи

Загружай при `stage:testing` и `stage:acceptance`, а также при запуске шаблона `acceptance_report`.

## Тестирование (stage:testing)
1. Загрузи скилл проекта `verify` и прогони применимое: сборка, тесты затронутых модулей, detekt, токены коммитов.
2. Поведение: тесты сторов/машин по функц. требованиям; тесты изменённого поведения идут вместе с реализацией (уже в PR).
3. Чужие ОС: `module-build.yml` на запушенной ветке — задачи затронутых модулей, один запуск на ОС; iOS — только `os=macos-15` (правила AGENTS.md).
4. Упало — читай лог (`gh run view <id> --log-failed`), воспроизведи локально, исправь; не перезапускай CI без просьбы пользователя.
5. Готово → переведи этап (шаблон `stage_advance`): доказательство (прогоны verify/CI), метка `stage:acceptance`, строка «Стадия:», доска. Запусти приёмку: кнопка «Приёмка» доски или шаблон `acceptance_report`.

## Приёмка (stage:acceptance)
1. Пройди acceptance criteria из функц. требований пункт за пунктом; фиксируй результат каждого.
2. Оформи под-issue «Приёмка: <тема>» (`type:artifact`, `source:agent`, sub-issue эпика): чек-лист с результатами, отклонения, замечания.
3. Пригласи пользователя подтвердить приёмку (ссылка на отчёт). Замечания → дефекты (`defect_flow`) или правки в PR.
4. Приёмку подтверждает человек; агент только готовит отчёт. Сохрани ссылку на явное подтверждение в отчёте/эпике вместе с полным head SHA проверенного PR и ссылкой на verify. Метка stage:acceptance означает ожидание решения и не заменяет подтверждение. При изменении проверенного head повтори проверку и запрос подтверждения.
5. Подтверждено → этап релиза: навык `release_prep`. Метку `stage:released` вешай только после фактической публикации релиза.

## Критерии готовности тестирования
- verify зелёный на head PR; чужие ОС проверены (если применимо).
- Все acceptance criteria имеют результат (пройдено/отклонение с причиной).
