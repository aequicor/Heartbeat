# Функциональные требования фичи

Загружай при `stage:spec`.

## Вход
Эпик в `stage:spec`, артефакты требований и дизайна (под-issue).

## Что сделать
1. Загрузи применимые скиллы проекта: `new-feature` (структура фичи api/impl), `state-machine` (состояния/переходы), `mvi-store` (сторы), `navigation` (маршруты), `di-metro`, `data-storage`, `network` — по необходимости.
2. Опиши в под-issue «Функц. требования: <тема>» (`type:artifact`, `source:agent`, sub-issue эпика):
   - **Сценарии**: Given/When/Then по каждому сценарию дизайна.
   - **Поведение**: состояния и переходы машины фичи, интенты, эффекты.
   - **Контракты**: интерфейсы `facade:api`, события, DI-привязки api→impl.
   - **Данные**: хранение (DataStore/Room), сетевое — если есть.
   - **Acceptance criteria**: проверяемый список для приёмки с привязкой к метрикам успеха.
   - **План работ**: порядок шагов/PR, каждый шаг коммитуемый и проверяемый (verify); риски.
3. Согласуй с пользователем; правки — правками под-issue.
4. Переведи этап (шаблон `stage_advance`): доказательство (ссылка на спеку), метка `stage:development`, строка «Стадия:», доска; дальше веди по `development_bridge`.

## Критерии готовности
- Каждый сценарий трассируется до метрики успеха.
- Контракты названы по модулям проекта; acceptance criteria проверяемы по пунктам.
- План разбит на шаги в пределах commit policy (25 000 токенов diff на коммит).

## Правила
- Код не начинаем до перевода в `development`.
