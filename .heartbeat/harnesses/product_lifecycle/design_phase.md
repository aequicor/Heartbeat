# Дизайн фичи

Загружай при `stage:design`.

## Вход
Эпик с согласованными бизнес-требованиями (под-issue артефакт).

## Что сделать
1. Загрузи скилл проекта `design-system` (токены, HbTheme, Hb-компоненты); при изменении интерфейсов агента — `service-as-ui`.
2. Предложи UX/UI: сценарии использования, структура экранов и навигация (скилл `navigation`), состояния каждого экрана (загрузка, пусто, ошибка), доступность.
3. Сверься с существующими паттернами Heartbeat: не изобретай новые компоненты без необходимости; отклонения от дизайн-системы явно обоснуй.
4. Зафиксируй в под-issue «Дизайн: <тема>» (`type:artifact`, `source:agent`, sub-issue эпика):
   - сценарии использования (по одному на метрику успеха);
   - схема экранов (эскиз или PlantUML `diagram`);
   - состояния экранов;
   - используемые токены и Hb-компоненты по имени;
   - открытые вопросы.
5. Согласуй с пользователем; итерации — правками под-issue.
6. Переведи этап (шаблон `stage_advance`): доказательство-комментарий (ссылка на под-issue дизайна), метка `stage:spec`, строка «Стадия:», доска.

## Критерии готовности
- Сценарии покрывают все метрики успеха из бизнес-требований.
- У каждого экрана определены состояния; список компонентов/токенов существует.
- Пользователь принял дизайн.

## Правила
- Дизайн-решения ссылаются на токены/компоненты дизайн-системы по имени.
- Код не трогаем — этап только про решение.
