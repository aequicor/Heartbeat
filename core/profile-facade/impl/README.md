# core:profile-facade:impl

Реализация [core:profile-facade:api](../api/README.md). **Подключается только в `:platform-main:di-bundle`.**

| Класс | Роль |
|---|---|
| `ProfileSessionsImpl` | `@SingleIn(AppScope)`. Операции сериализованы `Mutex`'ом; скоуп профиля `app/profile` — дочерний к app-скоупу |
| `InMemoryActiveProfileStorage` | дефолтный `ActiveProfileStorage` с `priority = Int.MIN_VALUE`; при старте пишет `log.w`, что профиль не переживёт смерть процесса |

## Порядок операций

Операции устроены так, чтобы их можно было вызывать из корутины закрываемого профиля.

```
open(id):  хранилище.write(id)   → новая сессия (скоуп + граф) → active = new → закрыть старый скоуп
close():   хранилище.write(null) → active = null                → закрыть старый скоуп
restore(): хранилище.read()      → новая сессия                 → active = new
```

После закрытия старого скоупа нет ни одной точки приостановки, поэтому вызывающая корутина не отменяется посреди
операции. Если граф профиля не удаётся создать, его скоуп закрывается, ошибка логируется и пробрасывается.

## Логи

Тег `ProfileSessions`: переключение сессии `p1 -> p2` / `p1 -> none` и итог `restore` (`I`). Тег `ActiveProfileStorage`:
чтение и запись (`D`). Скоупы логирует `core:di:impl` (тег `DI`).

## Тесты

Интеграционные, на реальном графе, в [platform-main/di-bundle](../../../platform-main/di-bundle/README.md):
- переключение профиля;
- восстановление в «новом процессе»;
- выход из корутины самого профиля с приостанавливающимся хранилищем;
- при смене профиля подписчики не видят `null`.
