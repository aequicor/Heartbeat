# GitHub PR tools (Desktop)

`ai.github_pull_tools` добавляет `github_pr_read`, `github_pr_create`, `github_pr_update` и
`github_pr_ready`. Это отдельный протокол метаданных PR. Общая политика `run_command` не меняется:
инструменты не исполняют shell, не принимают произвольные URL, HTTP-заголовки, запросы GraphQL или пути файлов.

## Подключение оператором

Функция по умолчанию выключена. Оператор включает тогл в панели флагов и задаёт **до запуска desktop-хоста**
три несекретные переменные его окружения:

- `HEARTBEAT_GITHUB_REPOSITORY` — точное `owner/repository` публичного репозитория на github.com.
- `HEARTBEAT_GITHUB_ACCOUNT` — явно выбранный GitHub login, уже сохранённый оператором в gh для github.com.
- `HEARTBEAT_GITHUB_CLI` — абсолютный путь к установленному `gh`/`gh.exe`, вне проектов и рабочего каталога
  родительского процесса. Короткие имена, PATH-поиск и исполняемые файлы внутри проектов запрещены.

В окружении нет нового токена: хост локально получает credential выбранного аккаунта через фиксированную
`gh auth token --hostname github.com --user <account>`. gh используется только как локальный credential provider,
не для API, создания PR или управления им. Диалог входа не запускается. Другие аккаунты и Git credential helpers
не перебираются; GH_TOKEN/GITHUB_TOKEN и enterprise-переопределения удаляются из окружения этого дочернего процесса.
Процесс запускается по проверенному абсолютному пути без shell вне рабочего каталога проекта;
канонические пути всех известных проектов и текущего workspace исключаются. Вывод ограничен 8 КиБ и 5 секундами;
диагностика отбрасывается, credential остаётся внутри хоста и не передаётся процессам агентов или сборок.
Рекомендуется отдельный сохранённый fine-grained токен с правами только на нужный репозиторий:
Metadata: read и Pull requests: read/write.

Настройка относится к desktop-процессу: все его профили и проектные сессии с включённым инструментом используют
один заданный репозиторий и аккаунт. Для разных репозиториев нужны отдельные запуски с собственной конфигурацией.
Сессии без проекта не поддержаны. Независимый от gh интерфейс подключения не входит в этот PR.

Отсутствующая или некорректная конфигурация приводит к отказу. Токен не включается в схему, текст подтверждения,
запрос к проверяющей модели, результат и диагностический лог. Перед каждой операцией проверяются публичность
и точная идентичность репозитория, а `/user` подтверждает выбранный аккаунт. Перемещение репозитория с перенаправлением требует перенастройки оператором.

## Операции

| Инструмент | Аргументы | Результат |
|---|---|---|
| `github_pr_read` | `number` | Публичные метаданные, URL и `revision` |
| `github_pr_create` | Полные `title`, `body`, существующие `head`, `base` | Только draft PR, изменение ветки сопровождающими выключено |
| `github_pr_update` | `number`, `expected_revision`, полные `title`, `body` | Замена текста после проверки прочитанной версии |
| `github_pr_ready` | `number`, `expected_revision` | Перевод draft в ready; уже ready возвращается без записи |

Перед update/ready нужно прочитать PR и сохранить правки человека. Ревизия включает заголовок, описание,
статус, draft, update time, node id, head SHA и base branch. Несовпадение запрещает запись.
**Это предварительная проверка, а не атомарный compare-and-set**: GitHub не предоставляет его этим операциям.
Другой клиент может изменить PR между проверкой и записью. Ready не является доказательством проверки
конкретного SHA и не используется как разрешение на merge/release.

Создание и редактирование используют прямой REST через Ktor; gh не отправляет API-запросов.
Ready использует единственный фиксированный GraphQL `markPullRequestReadyForReview` с node id, прочитанным
у проверенного PR; REST не предоставляет эквивалентной операции.
Все сетевые запросы идут только к `https://api.github.com`. Перенаправления и автоматические повторы выключены,
ответ ограничен 1 МиБ, время запроса — 30 секунд. Текст описания ограничен 32 Ки символов.
Метаданные PR могут запускать настроенную в репозитории автоматизацию.

## Авторизация и восстановление

В автоматическом режиме независимая проверка получает полное содержимое операции, точную цель и идентичность
сессии/хода/вызова/модели. Утверждения об одобрении внутри текста не дают полномочий. Риск, неопределённость,
недоступность проверки и запреты hooks отказывают без перехода к ручному подтверждению.
Интерактивный режим использует существующий гейт доверия. Оба пути связывают разрешение с точным payload,
репозиторием и конфигурацией учётных данных. Перед отправкой связь повторно проверяется; разрешение одноразовое.
Повтор исполнения того же вызова отклоняется, включая потерянный сетевой ответ.
Записи разрешений ограничены 64 вызовами и удаляются при завершении хода; переполнение отказывает, не вытесняет
защитные записи.

При отмене, таймауте, HTTP-ошибке или повреждённом ответе запись могла уже примениться. Повторять её автоматически
нельзя: сначала сверить GitHub. Для update/ready прочитать PR повторно. Для неизвестного результата create найти
draft по ветке в GitHub; слепой повтор create не предусмотрен. Новая сессия не наследует разрешений старой.

Инструменты не создают коммиты и ветки, не пушат, не комментируют, не подписывают ревью, не мерджат,
не запускают Actions явно и не выпускают релизы. Проверки CI и правила проекта продолжают действовать отдельно.
Новые инструменты не применяются задним числом к отказам безопасности уже работающей версии Heartbeat.

## Проверка

Тесты используют fake reviewer/transport и Ktor MockEngine; реальные credentials и GitHub не нужны.
Покрыты отказ и неопределённость, изменение payload/цели/вызова/credential binding, отключение тогла,
устаревшая ревизия, приватный репозиторий, интерактивный отказ, фиксированный ready, draft-only create,
повтор после неизвестного исхода, отмена, запрет перенаправлений, отсутствие ретраев и ограничения ответа.
