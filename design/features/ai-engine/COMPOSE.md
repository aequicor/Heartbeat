# Перенос согласованного Desktop-прототипа в Compose

Первый этап реализации, 2026-11-01. Основа — согласованный пользователем макет `ddd1ae48135a6ae9719249b87c4b60d47b38e938`, 133 кадра и 56 PNG. Ветка реализации: `codex/engine-ui-compose`. Это частичный перенос; согласование макета не означает завершения реализации всех его состояний.

## Реализовано

- В списке control panel только имя движка и отдельный статус «Не подключён / Выключен / Подключён». Галочка только у подключённого. Статус учитывает включение, пригодный runtime, сохранённый доступ и хотя бы одну выбранную модель на включённом binding.
- В панели вкладки «Обзор» и «Настройки». Настройки строятся из объявленных коннектором ConfigPage, файлов, ресурсов и импорта. Проектные настройки убраны из меню панели; их данные не удаляются.
- Рубильник включения в шапке. Выключенный обзор компактный, с обычной кнопкой включения и применимым удалением управляемой установки. Удаление требует подтверждения с фокусом на отмене; активный ход блокирует подтверждение, включая повторную проверку при отправке команды.
- Настоящий dropdown подключения с chevron. Ключ скрыт по умолчанию, eye/eye-off меняет password-семантику и имеет локализованные доступные имена. Убраны подпись о хранилище, ссылка на страницу ключей и отдельная кнопка проверки каталога.
- Модели выбираются независимыми чекбоксами. Редактирование хранит локальный черновик и сохраняет его одним действием. Ошибка записи сохраняет черновик; другие bindings не меняются. Новый binding завершается «Подключить», редактирование — «Сохранить», с соответствующими pending-подписями. Действие «Сделать основной» убрано из UI.
- Dropdown студии исключает отсутствующие точные targets каталога, подтверждённо недоступные/неподдерживаемые движки и bindings без источника авторизации. Сохранённый выбор и история остаются; другой аккаунт или модель не подставляются. Уже существующие классический старт и dropdown композера сохранены.

## Следующие этапы

1. Объединить подключения и агрегированные ресурсы с панелью в согласованные вкладки. Сейчас подключения сохраняют отдельный существующий экран, а ресурсы доступны через объявленные страницы конфигурации. Перенести оставшиеся развилки мастера установки и доступа.
2. Реализовать две настоящие проверки модели: запрос/непустой ответ и детерминированные пробы точности/признаков фишинга. Нужны revision-bound отчёты, общий UX-бюджет ожидания, обработка отмены/поздних результатов, жёлтая строка и модальное окно `i`. Текущий catalog refresh не доказывает успешный запрос. Основа — существующий `IsolatedPrompts`; его timeout не включает ожидание слота и non-cancellable cleanup, поэтому простой внешний timeout не гарантирует пятисекундный возврат UI.
3. Добавить контракт фактических effective settings с происхождением применённого значения. Затем подключить кнопку под композером и таблицу Heartbeat / движок / проект. Не строить таблицу по предполагаемому generic merge; не читать конфигурацию недоверенного проекта до проверки доверия.
4. Решить явное обновление доступности при старте: каталог движков после перезапуска имеет Unknown до refresh. Сейчас кешированные exact routes с Unknown сохраняются видимыми, чтобы не скрыть все восстановленные модели бессрочно. Требование только подтверждённо доступных моделей этим этапом выполнено не полностью.
5. Сохранить окно подтверждения удаления при ошибке операции. Сейчас ошибка показывается существующим banner после закрытия подтверждения.
6. Завершить визуальную сверку панели и оставшихся состояний с согласованными PNG, затем проверить приложение на Desktop.
