# Единый интерфейс движков — Desktop-прототип

Статус: **Desktop-макеты согласованы пользователем 2026-11-01**. [ai-engine.pen](ai-engine.pen) и [heartbeat.lib.pen](../../system/heartbeat.lib.pen) сохранены и независимо проверены через MCP. Это согласованный прототип; реализация приложения в этот шаг не входит. Стандарт: [connect-engine](../../../.claude/skills/connect-engine/SKILL.md).

## Принятые решения

- Один движок имеет общую установку в профиле, несколько подключений и настройки проектов. В чате выбирается точная связка **модель · движок · подключение** без скрытого переключения аккаунта.
- Встроенный движок — Koog. Pi и другие CLI исполняются отдельно; версия и источник показаны в разделе установки.
- В списке движков есть отдельные текстовые индикаторы «Не подключён», «Выключен», «Подключён». Галочка есть только у «Подключён»; у двух остальных состояний иконок нет. Выключение имеет приоритет. «Подключён» означает включённый движок, доступный совместимый runtime, сохранённое подключение и хотя бы одну выбранную модель. Этот индикатор не подтверждает успешный запрос или безопасность ответов и не меняется из-за результата проверки моделей. Проблема или неполная проверка обозначаются жёлтой строкой модели и кнопкой `i` с подробностями в модальном окне; при успехе дополнительных отметок нет. Ограничения проекта показываются в его контексте.
- Обычная строка списка содержит имя и статус. Подзаголовков нет; ошибки и следующие действия показаны внутри панели движка. Подсказка «Проверьте установку» в списке не дублируется. Строки без подсказок компактнее.
- Мастер внешнего движка: **установка → доступ → модели**, без отдельного шага проверки. Новое подключение завершается **«Подключить»**, редактирование — **«Сохранить»**. Сначала только «Проверить локально», включая совместимость по коннектору. После локальной проверки доступна альтернатива «Скачать стабильную версию для Heartbeat», даже если пригодная установка найдена. Стабильная версия — закреплённая совместимая сборка коннектора. Если установка не найдена — ручной выбор расположения или скачивание. Рядом с загрузкой: «Эта установка будет удалена вместе с Heartbeat». Ошибка поиска и неизвестный результат не означают отсутствие установки.
- Шаг «Доступ» предлагает подписку, готовые настройки провайдеров, OpenAI-совместимый или Anthropic-совместимый API — только поддерживаемые коннектором варианты. Для Pi предусмотрены ключи планов Z.ai/Qwen, пресеты OpenAI/Anthropic/Google и совместимые API; для Codex — вход ChatGPT. Совместимый сервер требует имени, адреса и ключа. Ошибка адреса исправляется до отправки секрета; после доступа остаются выбор моделей и сохранение.
- **Отдельной страницы ключей и кнопки «Открыть страницу ключей» нет**: ключ находится внутри формы конкретного подключения при создании и редактировании. При каждом открытии он скрыт по умолчанию; **eye / eye-off** явно показывает и скрывает поле. Подзаголовок о защищённом хранении убран; требование хранить ключ в профильном секрет-хранилище сохраняется.
- Используемые модели выбираются **множественно, checkbox у каждой модели**. Выбор одной модели не снимает другие. Обычная галочка списка обозначает выбранную модель, а не успех проверки. После «Подключить»/«Сохранить» выполняется короткая bounded синхронная проверка двух аспектов для добавленных или изменённых связок; во время операции кнопка показывает **«Подключение…»/«Сохранение…»**, остальные действия не дублируют запрос. Общий бюджет ожидания UI — около 5 секунд на всю операцию.
- Незавершённый черновик мастера не сохраняется; отмена редактирования не удаляет прежние данные. Завершённая установка, сохранённые подключения, настройки, выбор моделей и история сохраняются независимо от исхода проверок. Ошибка, таймаут или Unknown не удаляют и не подменяют выбранную связку.
- В обзоре — рубильник включения в постоянном месте. В выключенном состоянии дополнительно обычная «Включить» перед «Удалить установку»; повторные строки установки и подключения убраны. Удаление доступно только для установки Heartbeat и требует модального подтверждения. Начальный фокус — «Отмена»; активный ход не прерывается.
- Раздел называется «Модели». Подключение раскрывает провайдера и способ доступа, например «Anthropic · API-ключ». У dropdown названия подключения есть **явный chevron**, видимый без наведения. Имя не заменяет идентификатор подключения и не содержит секретов. В обзоре нет «Начать чат» и «Сделать основным».
- Новый чат наследует применимые параметры последнего фактически начатого рабочего чата. У проекта может быть предпочтительная связка. Недоступность требует явного выбора, а не автоматической подмены.
- Стартовый чат сохраняет классический вид «Что создадим?» с полем ввода и быстрыми действиями. При отличиях под полем есть текстовая кнопка **«Настройки проекта отличаются»**, открывающая `HbDialog`. Таблица: **Параметр | Настройка Heartbeat | Настройка движка | Настройка проекта**. Цвет и подпись «Применяется» отмечают эффективное значение в каждой строке; источники могут различаться. «Не задано» отличается от выключенного значения. Для инструкций показана итоговая композиция. Приоритет применяется только в пределах разрешённых коннектором полей доверенного проекта; недоверенные настройки не читаются. Сравнение не меняет настройки, Esc/Закрыть возвращают фокус кнопке под вводом.

## Короткая синхронная проверка подключения/сохранения

После «Подключить» или «Сохранить» сохраняются настройки и выбор моделей, затем в рамках той же операции автоматически проверяются два аспекта каждой добавленной или изменённой связки **движок × подключение × модель**. Изменение доступа, endpoint или ключа затрагивает все выбранные модели подключения. Неизменённая связка не перепроверяется при открытии/закрытии формы или сохранении без изменений. Результаты принадлежат профилю и привязаны к сохранённой ревизии: ответ прежней проверки не подтверждает новую настройку.

**UX-бюджет — около 5 секунд на всю операцию**, от нажатия до завершения ожидания, включая сохранение и оба аспекта всех затронутых моделей. Это цель и верхняя граница ожидания UI, **не обещание скорости провайдера** и не отдельный бюджет на каждую модель/пробу. Синхронность относится к операции в UX; UI-поток не блокируется. До завершения кнопка показывает **«Подключение…» / «Сохранение…»** и недоступна для повторного запуска; повторный клик и остальные действия не дублируют сохранение или проверочные запросы.

1. **Реальный запрос и непустой ответ.** Небольшой запрос по точному маршруту должен завершиться непустым ответом модели. Handshake, каталог моделей, HTTP-успех или открытие потока сами по себе не считаются успехом.
2. **Простые детерминированные пробы.** Фиксированные задания и заранее заданные критерии проверяют ошибочные/выдуманные ответы и признаки фишинга: например, ответ по известным фактам и отсутствие выдуманных сведений, просьб передать секрет или перейти на посторонний адрес. Детерминированы задания и оценка, а не произвольная генерация модели. Ссылки из ответов не открываются. Результат — наблюдение на этих пробах, **не гарантия безопасности и не утверждение намерения модели или провайдера**.

Если срок вышел, **сохранение завершается**, незавершённые пробы отменяются, а модели с неполной проверкой получают жёлтую строку и `i`. UI больше не ждёт ответа или подтверждения отмены от провайдера; поздний ответ не превращает завершённую неполную проверку в успех. Обрыв, пропуск, таймаут, исчерпание лимита и Unknown / «Результат неизвестен» не считаются успехом; успех реального запроса не подменяет результат проб качества/фишинга. Отдельного блока **«Проверка моделей» нет**.

- **Оба аспекта успешны:** обычная строка модели без отчётов, текста об успехе, success badges, новой проверочной галочки или кнопки `i`. Обычная галочка выбора остаётся допустимой.
- **Неточность, ошибочный/пустой ответ, признак фишинга, неполная проверка или Unknown:** жёлтая строка модели и доступная кнопка **`i`**, видимая без наведения. У кнопки есть доступное имя «Подробности проверки модели» и управление с клавиатуры (Tab, Enter/Space); проблема обозначена не одним цветом.
- Нажатие `i` открывает **модальное окно `HbDialog`** с двумя раздельными результатами — реальный запрос/непустой ответ и пробы качества/фишинга. Для каждого показаны исход, проба, ожидаемый результат, фактический ответ и объяснение. При неполноте указаны причина и недостающие данные, без выдуманного ответа. Действия: **«Повторить проверку»** и **«Закрыть»**; Esc закрывает окно, фокус возвращается к `i`. Открытие/закрытие подробностей не отправляет запросы. Явный повтор проверяет оба аспекта текущей сохранённой ревизии с тем же общим бюджетом; пока он идёт, повторный запуск недоступен. При успехе жёлтая отметка и `i` исчезают, диалог закрывается с фокусом на строке модели, отчёт об успехе не появляется.

Проблемы предупреждают **без блокировки** работы или сохранения; настройки, подключения и выбор моделей по результатам не удаляются и не подменяются. По завершении операции, включая истечение бюджета ожидания, сохранённые модели доступны в «Модели и движки» и рабочем чате. Независимые ограничения совместимости runtime, корректности адреса и общей безопасности продолжают действовать.

Проверки выполняются в изолированных служебных сессиях **без hosted/native инструментов, MCP, доступа к секретам, проектным файлам, проектным инструкциям и истории рабочего чата**. Авторизация выбранного подключения используется только транспортом; ключ не попадает в промпты, ответы и логи. При невозможности обеспечить изоляцию непроведённая проверка отмечается жёлтой строкой и `i` с причиной, не успехом. Расход ограничен заранее заданной квотой запросов/токенов на связку, ожидание — общим бюджетом операции; расход квоты объясняется рядом с действием запуска/повтора, без отдельного отчёта при успехе. Обе проверки **не обновляют последний начатый рабочий чат и его параметры**, не подтверждают все возможности проекта и не заменяют регрессию коннектора.

## Границы проверки и продолжение

Это статический прототип: авторизация, запуск движка, списание квоты, удаление runtime и работа проектных настроек в приложении здесь не тестировались. Удаление установки вместе с Heartbeat — принятое требование жизненного цикла, которое предстоит реализовать и подтвердить отдельно для каждого способа распространения.


Desktop-прототип согласован. Tablet/Phone и Compose-реализация в этот шаг не входят; их реализация — отдельная задача. Объединение текущих разделов управления представлено как предложение прототипа.

## Уточнение границ панели

В строках движков только имя и статус, без subtitle. В селекторе чата — только доступные связки; недоступное прежнее значение не остаётся в списке или композере, альтернативу выбирает пользователь. Настройки и история не удаляются. Вкладка «Проекты» заменена на «Настройки» движка/коннектора: навыки, расширения и шаблоны промптов Pi как примеры объявленных возможностей. Проектные параметры вынесены из этой панели; их сравнение по-прежнему доступно под вводом чата.

Выбор модели в чате выполняется только через dropdown-menu у поля ввода. В нём только доступные связки модели/движка/подключения. Отдельных экранов выбора и workflow «Модель недоступна → явная альтернатива» нет; утрата доступности обновляет содержимое dropdown без автоматического выбора другой модели.

Новая сессия всегда открывается стандартным экраном «Что создадим?» с полем ввода. Панель настроек движка — самостоятельный раздел, без пользовательского пути через доверие проекту, выбор обязательного режима или отдельный экран требования/ошибки проекта. Состав настроек различается по объявленным возможностям движка/коннектора; компоненты, виджеты и правила раскладки общие. Проверки разрешений и ошибки проекта остаются в контексте затронутого действия и не подменяют стартовый экран. Сравнение эффективных параметров доступно через кнопку под вводом.
