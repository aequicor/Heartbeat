# Единый интерфейс движков — Desktop-прототип

Статус: **на согласовании**. [ai-engine.pen](ai-engine.pen) — предложение UI, а не реализованное поведение приложения. Библиотека: [heartbeat.lib.pen](../../system/heartbeat.lib.pen). Стандарт подключения: [connect-engine](../../../.claude/skills/connect-engine/SKILL.md).

## Принятые решения

- Один движок имеет общую установку в профиле, несколько подключений и настройки проектов. В чате выбирается точная связка **модель · движок · подключение** без скрытого переключения аккаунта.
- Встроенный движок — Koog. Pi и другие CLI исполняются отдельно; версия и источник установки показываются явно.
- Мастер внешнего движка: **установка → доступ → модель → проверка**. Сначала только «Проверить локально», включая совместимость по коннектору. Если установка не найдена — «Выбрать расположение вручную» или «Загрузить для Heartbeat». Рядом с загрузкой: «Эта установка будет удалена вместе с Heartbeat». Ошибка поиска и неизвестный результат не означают отсутствие установки.
- Проверочный запрос обязателен перед первым рабочим чатом выбранной связки. Он расходует квоту, не обновляет параметры последнего рабочего чата и не подтверждает все возможности проекта.
- Незавершённый черновик мастера не сохраняется. Завершённая установка, подключения и история сохраняются независимо. Подтверждённо недоступный вариант убирается из сохранённого выбора; ещё не проверенный результат с ним не смешивается.
- В обзоре — рубильник включения в постоянном месте. В выключенном состоянии дополнительно обычная «Включить» перед «Удалить установку»; повторные строки установки и подключения убраны. Удаление доступно только для установки Heartbeat и требует модального подтверждения. Начальный фокус — «Отмена»; активный ход не прерывается.
- Раздел называется «Модели». Подключение раскрывает провайдера и способ доступа, например «Anthropic · API-ключ». В обзоре нет «Начать чат» и «Сделать основным».
- Новый чат наследует применимые параметры последнего фактически начатого рабочего чата. У проекта может быть предпочтительная связка. Разрешённая конфигурация доверенного проекта приоритетнее настроек Heartbeat; отличия видны при начале сессии. Недоступность требует явного выбора, а не автоматической подмены.

## Проверка 2026-11-01

- Все 38 состояний просмотрены в обеих темах, включая длинные подписи, ошибки и восстановление. После нормализации отступов отдельно проверены 63 изменённые области, включая копии в путях.
- Сохранённая версия открыта из изолированной рабочей копии через MCP. Подтверждены последние правки мастера, выключенного обзора и удаления, а также новый библиотечный шаблон `HbDialog / Confirmation / Desktop` (`GqRKo`).
- MCP: 103 кадра, 38 тёмных; нет дублирующихся ID, локальных reusable-компонентов, переменных вместо размеров, активных placeholder, устаревших подписей или layout diagnostics.
- Исходные `.pen` и перенесённые в ветку PR файлы побайтово совпадают (SHA-256). Файлы сохранены; computer-use для pen.dev не использовался.
- Код Kotlin/Gradle не изменён: сборка и detekt для этого шага не требуются.
- Обязательный прогон `python -X utf8 -m unittest discover -s scripts/tests -v` на Windows после исправления переносимости тестов: **132 теста, 127 прошли, 5 прежних Unix-only тестов пропущены, ошибок нет**. OpenSSL доступен через `Git/usr/bin` в `PATH`; Bash выбирается по абсолютному пути к Git Bash, без возврата к WSL. Добавлены проверки выбора Bash для Windows и POSIX. Тесты macOS-бандла на Windows проверяют запрос `chmod(0755)` и точные аргументы `Path.symlink_to`; на POSIX сохранены проверки фактических прав и настоящей ссылки. Состав пакета, подпись и отказ постороннему payload проверяются на всех хостах. Production-скрипт установщика не изменён.
- Проверки whitespace и бюджета каждого коммита выполняются перед публикацией; фактические итоги указаны в PR.

## Границы проверки и продолжение

Это статический прототип: авторизация, запуск движка, списание квоты, удаление runtime и работа проектных настроек в приложении здесь не тестировались. Удаление установки вместе с Heartbeat — принятое требование жизненного цикла, которое предстоит реализовать и подтвердить отдельно для каждого способа распространения.

Ожидается явное согласование всего Desktop-прототипа. Tablet/Phone и Compose-реализация в этот шаг не входят; к ним переходить после согласования. Объединение текущих разделов управления представлено как предложение прототипа.
