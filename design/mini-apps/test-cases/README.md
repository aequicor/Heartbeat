# Мини-апп «Тест-кейсы» (service-as-ui, харнесс `testcases`)

Макет: [test-cases.pen](test-cases.pen) — Desktop, светлая/тёмная. Кадры:

- **Chat card** — основной вид: каноническая `card` в ленте беседы (компактно: вкладки, поиск, 5 строк, «Показать ещё»), кнопка мини-аппа (✦) в композере, «развернуть» в карточке.
- **Chat card · case dialog** — клик по строке открывает именованную модалку `case` поверх беседы.
- **Start · Cases / Run / Changes / Empty** — тот же app на всю область контента (старт нового чата; из композера/«развернуть» — модалка хоста).
- «Пользовательские пути». Tablet и Phone — после согласования Desktop (на мобильных харнесс не исполняется).

Размещение (`placement:"card"`): запись в ленте от `ui_show`, кнопка в композере и полный app на старте создаёт хост; отдельная панель не нужна.

## Решение: нативные узлы, не WebView

Проверено по справочникам `service-as-ui` и API харнесса:

- Кнопки «Править/Новые кейсы/Закоммитить через агента» — нативное действие `prompt` (`submit:false`: текст вставляется в чат). Из WebView
  его вызвать нельзя (мост даёт только `heartbeat.call`), а `sessions.send` из метода харнесса ограничен: 6/мин и 3 хода харнесса подряд без реплики пользователя.
- Нативный UI даёт компоненты хоста (Hb-стиль, тема, доступность) и рендерится без WebView; детали кейса — именованная модалка `case`.
- Нативного master-detail и живого поиска нет: вкладки — `set view` + `if`; фильтры и поиск — `sequence [set, reload snapshot]` с `args` из state;
  строка таблицы — `sequence [call get_case → state.current, open.modal case]`; группировка — сортировка по «Набору» у владельца; пагинация — страница из метода.

## Данные и чтение репозитория

Источник истины — `testcases/**/*.md` (Markdown, YAML-шапка с **однострочными** значениями, `covers: [a, b]`). Скрипт харнесса запускает объявленные
`commands.define` (нужны `harness.commands` и проектный чат, только Desktop); в параметрах и словах argv запрещены `^ | ( ) " & < > % !`, поэтому:

| Метод | Команды | Заметки |
|---|---|---|
| `snapshot` (auto source, read-only) | `git grep --untracked -n -F -e id: -e title: -e status: -e priority: -e type: -e tags: -e covers: -- testcases` | строки шапки отбирает Kotlin; вывод ограничен (голова/хвост + маркер пропуска) — отдавать страницы |
| `get_case {id}` | `git grep --untracked -n -F "" -- {path}` (path — regex-параметр) | шаги разбирает Kotlin |
| `get_diff {path}` | `git diff HEAD -- {path}`; для untracked `git diff --no-index -- /dev/null {path}` | |
| `changes` | `git status --porcelain -- testcases` | |
| `record_step {id,step,result,comment?}` | — | `data` харнесса (≤256 КБ), не репозиторий |

Запись в репозиторий — только агентом (по `prompt`). Автообновление карточки: правки в файлах не меняют `data`, поэтому `events.on<SessionEvent.TurnFinished>`
пишет в `data` счётчик ревизии (это инвалидирует surface) + кнопка «Обновить».

## Допущения, которые надо проверить вживую

1. Ширина колонки нативного app (в макете 760) и вид `table` в полной карточке.
2. Привязка `args` источника к `state` в `sequence` с `reload` (проверит `ui_put`).
3. Показ diff только как markdown-блок кода, без построчной подсветки.

## Открытые вопросы

1. Нумерация `TC-NNNN` (дубли между ветками ловит CI) или slug-идентификаторы.
2. `runs/` в git или в `.gitignore`.
3. Нужен ли read-only вид на мобильных (потребует другого источника данных, чем команды харнесса).
