# Компоненты Heartbeat

Публичные виджеты находятся в `io.aequicor.heartbeat.ds.components` и используются внутри `HbTheme`:

- По умолчанию `HbButton` и `HbTextField` используют плотный плоский стиль студии (`HbVisualStyle.Flat`): тихие заливки состояний и контур фокуса только при клавиатурной навигации. В `HbVisualStyle.Platform` кнопки делегируют действия выбранному платформенному киту. Поля во всех стилях используют общий Foundation-редактор с доступным scroll state и полосой прокрутки; значение контролирует вызывающая сторона.
- `HbText`, `HbCard`, `HbBadge` используют токены и семантический `HbTone`. Поверхности плоские: непрозрачная заливка и hairline, без теней; тень есть только у всплывающих поверхностей (`hbPopupSurface`).
- Настройки и состояния: `HbSettingsSection`/`HbSettingsRow`, `HbDialog`, `HbBanner`, `HbEmptyState`, `HbLoadingState`, `HbPaneHeader`.
- `HbChatMessageBubble` отображает текст, код, результат инструмента и уведомление. Для специализированного сообщения предусмотрен слот `content`.
- `HbChatTranscript` принимает неизменяемый список `HbChatMessage`. Новый фрагмент ответа передаётся заменой `text` с сохранением `id`; одинаковые идентификаторы запрещены.
- `HbChatComposer` принимает текст, `onValueChange`, `onSend`, `onStop` и локализованные подписи. Отправка доступна для непустого текста; во время генерации отображается остановка. `Ctrl/Cmd+Enter` отправляет, обычный Enter добавляет строку.

`Modifier.hbSurface` даёт ту же плоскую поверхность специализированным компонентам. `HbButtonStyle.Ghost` оставляет второстепенное действие без заливки до наведения, сохраняя семантику кнопки и клавиатурный фокус. Composer располагает цельное поле над нижней панелью действий; для короткого окна `inputMaxHeight` можно ограничить минимальной высотой поля.

`HbPanel` выделяет функциональную область непрозрачной заливкой и тонкой
границей, без собственной тени, отступов и прокрутки. `HbDivider` отделяет связанные
секции внутри области. Эти Foundation-компоненты общие для всех платформенных китов;
панель не обрезает дочерние тени. В sandbox навигация, диалог с панелью действий и ввод
образуют отдельные области. Подробности, консоль и diff инструмента имеют компактные
заголовки с разделителем; абзацы ответа остаются на одной читаемой поверхности.

`HbMessageAppearance` задаёт фон, цвет текста, семантический тон, долю ширины и расположение каждого сообщения. `Color.Unspecified` наследует тему. При явном переопределении пары цветов вызывающий код отвечает за контраст. `Automatic` располагает пользовательские сообщения справа, системные — по центру, остальные — слева; `Start`/`Center`/`End` переопределяют это правило.

Транскрипт использует виртуализированный список с устойчивыми ключами и привязкой к нижней границе. Поток продолжает прокрутку, пока пользователь у последних сообщений. Просмотр истории, включая верхнюю часть длинного ответа, приостанавливает следование. Возврат вниз или действие «К последнему» включает его снова. Восстановленное положение истории сохраняется. `LazyListState` можно передать снаружи.

Текст сообщения выделяется для копирования. Код поддерживает горизонтальную прокрутку. Изменение статуса генерации объявляется через вежливую live region; каждый фрагмент ответа не озвучивается заново. Все подписи передаются снаружи, поэтому язык не зашит в компоненты.

Компоненты не вызывают агента, сеть или хранилище. Журнал содержит действия и длину текста, без содержимого сообщений. Примеры всех вариантов представлены в `design-system:catalog` и отдельном `platform-main:uikit-sandbox`.

## Богатая история

Новый основной overload: `HbChatTranscript(timeline = ...)`.

```kotlin
val today = HbChatSection("today", localizedToday)
var timeline = HbChatTimeline.from(today, initialMessages)
timeline = timeline.append(today, nextMessage)
timeline = timeline.replaceLatest(nextMessage.copy(text = streamedText))
timeline = timeline.prepend(olderSection, olderPage)
// Карточки хоста после истории: снимок для отрисовки, история хранится отдельно.
rendered = timeline.appendTail(today, hostCards, previous = rendered)
```

Timeline использует persistent-коллекции. Подготовка Markdown выполняется при изменении
сообщения, не при прокрутке. Длинные абзацы/код разбиваются на bounded chunks с ключами,
основанными на ID сообщения и смещении источника. Неизменённые строки сохраняются.
`appendTail` добавляет записи хоста (например, карточки worktree) после истории и переиспользует их
подготовленные чанки из прошлого снимка; `latestMessage` снимка — последняя запись хвоста, поэтому
стриминг идёт в timeline истории, а хвост добавляется заново на каждом обновлении.
Legacy overload `messages` оставлен для небольших списков и собственного body slot.

`HbMarkdown` — самостоятельный ограниченный viewport; в длинном transcript используйте
подготовленные `HbMarkdownBlockContent` внутри внешнего списка. Markdown не исполняет HTML,
не загружает remote images и не открывает ссылки без `onLinkClick` владельца.

Fenced code с языком получает подсветку Kotlin/Java/JS/TS/JSON/Python/shell в обеих
темах. Для обычного `HbMessageKind.Code` укажите `codeLanguage = "kotlin"`.
Неизвестный язык отображается без подсветки. `highlightHbCode` возвращает неизменяемые
UTF-16 диапазоны; парсер нарезает их вместе с текстом, сохраняя контекст многострочных
комментариев и строк. При ручном создании `HbMarkdownBlock` поле `codeSpans = null`
включает подготовку по его `language`; пустой список явно оставляет текст без подсветки.

В `HbChatTranscript(timeline)` заголовок инструмента и раскрытые Markdown/Console/Diff
становятся строками того же lazy-списка. Вложенной вертикальной прокрутки нет; длинные
результаты разбиты на ограниченные фрагменты. `rememberHbToolExpansionState()` сохраняет
раскрытие независимо от lazy disposal. Для внешнего управления передайте его через
`toolExpansionState`, затем вызывайте `setExpanded(messageId, toolId, isExpanded)`.

Standalone `HbToolCallView` показывает состояние и сводку небольшого результата.
Статус в заголовке — контрастная текстовая метка с символом, без кнопочного фона.
Действие раскрытия принадлежит всей строке заголовка.
Раскрытие управляется снаружи или сохраняется через `rememberSaveable` по ID. Его обычный
Column не имеет вертикальной прокрутки. Для больших результатов используйте timeline.

`HbToolBlock.Console` отображается на сплошном графитовом фоне. Команды, служебный
вывод, успешное завершение, предупреждения и ошибки различаются цветом строки.
Неизвестный текст сохраняется без интерпретации. Панель остаётся цельной между
lazy-сегментами; исходный текст и смещения сохраняются при подготовке.
Код сохраняет горизонтальную прокрутку, буквальный вывод и семантические цвета +/- строк.

`HbDiffView(text, labels)` — отдельная компактная панель изменений. Каждый файл
получает заголовок с выделяемым путём и кнопкой копирования полного пути, даже если
подпись сокращена по ширине. Кнопка доступна с клавиатуры, показывает подтверждение
копирования и сообщает результат через accessibility. Подписи передаются в `HbToolLabels`.
Путь берётся из пары `---`/`+++`; для удаления используется старый путь, для переименования
— новый. Без надёжного заголовка выводится локализованное название без кнопки копирования.
Raw diff сохраняется полностью. В чате файлы разбиваются на bounded lazy-сегменты
с общим фоном; каждый заголовок выводится только один раз. Standalone-компонент
подходит для небольших результатов, большие следует отображать через timeline.

`HbComposerMenuButton` принимает immutable-команды и controlled expanded-state.
В sandbox команды вставляют локальные примеры и подготавливают 10 000 сообщений;
они не обращаются к файловой системе, модели или внешним плагинам.

Composer и закреплённые заголовки — непрозрачные поверхности поверх истории; blur не используется.

Все scrollable-поверхности имеют auto-hide scrollbar, включая код, таблицы, консоль,
diff, меню, панели composer и сам текстовый редактор. Полоса появляется при прокрутке
или наведении на её область, не сдвигая содержимое; перетаскивание использует тот же
scroll state. В sticky host она находится вне маски затухания и не дублируется внутри
LazyColumn. Для длинной истории размер thumb не пересчитывается по видимым строкам.

## Иконки

Набор включает 110 иконок. Полный неизменяемый список — `HbIcons.All`.
В sandbox у иконок отдельный раздел: семь категорий, поиск по имени, образцы
14/18/24 dp и выделяемые API-имена. `Loading` — статичный знак; движение,
если оно нужно экрану, контролируется его состоянием и reduced motion.

`HbIcons` — единый набор тонких скруглённых векторов. `HbIcon(HbIcons.Folder,
contentDescription = null)` рисует иконку размером `HbTheme.dimensions.iconSize`;
для метаданных используйте `Modifier.size(HbTheme.dimensions.iconSmallSize)`.
Цвет задаётся через `tint` из `HbTheme.colors`. Доступное название задаёт кнопка
или сама иконка, если рядом нет подписи. `HbComposerMenuButton` принимает
`icon = HbIcons.Plus` и сохраняет прежние управление фокусом и область нажатия.

## Иллюстрации

```kotlin
HbIllustration(
    illustration = HbIllustrationKind.EmptyWorkspace,
    contentDescription = null, // The adjacent localized text describes this state.
)
```

Восемь оригинальных векторных сцен: Welcome, EmptyWorkspace, EmptyChat, NoResults,
Success, Error, Offline и Upload. Общий Foundation-рендер для Material, Fluent и macOS,
размер по умолчанию 240×180 dp (`HbDimensions.illustrationWidth/illustrationHeight`),
палитра из `HbTheme.colors`. Смена темы пересоздаёт вектор; обычные рекомпозиции его
переиспользуют. Размер можно изменить модификатором, пропорции сохраняются.
Если подписи рядом нет, передавай локализованный `contentDescription`.
Галерея и светлое/тёмное превью — в отдельном разделе «Иллюстрации» sandbox.
