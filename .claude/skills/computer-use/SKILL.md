# Computer use: работа движка с инструментами `computer_*` и `window_*`

Инструменты управляют реальным экраном пользователя. Это привилегия, а не песочница: каждое
действие видно человеку, а ошибка ввода попадает в его окна. Фича доступна только на Desktop
Windows/macOS и включена, если инструменты появляются в наборе.

Два семейства инструментов соответствуют двум режимам захвата:

- `computer_*` — весь рабочий стол (или один монитор): `computer_capture {monitorId?}`;
- `window_*` — одно окно приложения: `window_list`, затем `window_capture {windowId}`.

У обоих семейств одинаковые глаголы: `_capture`, `_screenshot`, `_zoom`, `_roi`, `_click`, `_drag`,
`_scroll`, `_type`, `_key`, `_release`; `computer_status` общий. Ниже `<f>` — префикс семейства
активного захвата. Инструмент другого семейства отвечает `CaptureModeMismatch`, пока ты не захватишь
его `_capture` (захват переключается без отдельного release). Ввод (`<f>_click`,
`<f>_drag`, `<f>_scroll`, `<f>_type`, `<f>_key`) и `<f>_release` проходят
гейт доверия сессии: в зависимости от уровня доверия пользователь подтверждает их и может отклонить
(«The user declined this action» — не повторяй тот же вызов; «The action changed while awaiting
approval; request it again» — сделай свежий снимок и вызови заново). `<f>_capture`
подтверждения не спрашивает, но захват сразу виден пользователю, поэтому работай аккуратно и экономно.

## Обязательный порядок работы

1. **`computer_status`** — всегда первым вызовом: права, мониторы, активный захват (`family`, `roi`), `inputArmed`.
2. **Захват** — старт или смена:
   - работа в границах одного приложения — `window_list`, затем `window_capture {windowId}` (точнее по
     пикселям, ввод гарантированно остаётся в окне);
   - задача между приложениями или по всему экрану — `computer_capture`; один монитор — `monitorId`
     из `computer_status`, без него кадр покрывает объединение мониторов.
   - первый кадр приходит изображением в ответе на захват — отдельный снимок или `read` не нужен.
3. **`<f>_roi`** — сузь рабочую область до нужной части экрана (см. «ROI»), когда работаешь с её частью.
4. **`<f>_screenshot`** — свежий кадр; **`<f>_zoom`** — чтение мелкого текста. Оба
   возвращают изображение вместе с геометрией одним ответом: смотри его сразу, без отдельного `read`.
5. **Ввод** — `<f>_click`, `<f>_drag`, `<f>_scroll`, `<f>_type`, `<f>_key`.
6. **`<f>_release`** — сразу по завершении работы; кадры сессии удаляются. Захват также
   освобождается автоматически в конце хода.

После каждого шага изменения экрана делай свежий `<f>_screenshot`: решения по устаревшему
кадру — главная причина ложных кликов.

## ROI (rectangle of interest)

ROI — рабочая область захвата: прямоугольник master-кадра, которым ограничены кадры, тайлы, zoom и ввод.

- `<f>_roi {roi:{x, y, width, height}}` задаёт ROI и возвращает кадр ROI; `{tile:"c:r"}` — тайл как ROI;
  `{clear:true}` — сброс на весь захват. `roi.space`: `preview` (по умолчанию — пиксели последнего
  полученного кадра), `master` или `normalized` (доли 0..1 master-кадра).
- После установки снимки показывают только ROI, а пиксели кадра отсчитываются от её левого верхнего угла
  (поле `roi` в ответе кадра — где она в master-кадре). Тайлы раскладываются по ROI.
- Точка ввода, `roi` снимка или zoom вне активной ROI отклоняются `OutsideRoi`: расширь или сбрось ROI.
- ROI сбрасывается сама при новом захвате и когда окно изменило размер так, что она не помещается.

## Запись (видео-режим)

Доступна, когда в наборе есть `<f>_record` (тогл `computer_use.recording`).

- `<f>_record {durationMs?, fps?, untilStable?, maxFrames?}` снимает активную ROI с частотой `fps`
  (1–10, по умолчанию 4) до `durationMs` (200–10 000, по умолчанию 3000) или до успокоения экрана
  (`untilStable`, по умолчанию true: ~0,8 с без изменений, без изменений вовсе — 1,5 с).
- Ответ — до `maxFrames` (2–6) ключевых кадров изображениями по порядку и JSON с `tMs` каждого, `roi`
  (кадрирование по области изменений — `autoRoi: true`), `stable`, `changed`. Последний кадр — текущий
  экран: координаты ввода дальше отсчитываются от него.
- `observeMs` у `<f>_click/_drag/_scroll/_type/_key` (до 5000) записывает сразу после ввода — смотри так
  открытие меню, загрузку, анимацию вместо серии снимков. Ввод уже применён, даже если запись не удалась
  (`observation failed` в ответе).
- Окно сессии и индикаторы скрываются только на время каждого кадра (кнопка «Стоп» остаётся доступной),
  курсор в кадры не попадает. Zoom работает только по последнему кадру клипа (`UnknownCapture` для ранних).

## Координаты и кадры

- Координаты ввода — пиксели **последнего полученного кадра** (снимок, zoom, кроп). Другое
  пространство задаётся явно: `space` = `preview` | `master` | `normalized` | `screen`.
- `<f>_screenshot` возвращает уменьшенный кадр ROI и сетку тайлов; `tile: "колонка:строка"`
  (с нуля, по ROI) или разовый `roi` внутри активной ROI режут кадр, `<f>_zoom` вырезает
  область master в нативном разрешении — им и читай мелкий текст, не угадывай по превью.
- `RegionOutOfBounds` — точка или область вне последнего кадра: возьми новый снимок и пересчитай
  координаты, не двигай точку наугад.
- `StaleFrame` / `TargetResized` — экран изменился: свежий снимок обязателен перед повтором.

## Ввод

- **`<f>_click`**: `count` 1–3 (двойной/тройной клик — `count`, не повтор вызова). Правый и
  средний клики — через `button`.
- **`<f>_drag`**: перетаскивание между двумя точками одного кадра; для выделения текста
  сначала щёлкни в позицию, потом тащи между пикселями одной строки.
- **`<f>_scroll`**: `deltaY` в пикселях, 40 px = один «щелчок» колеса (округление до ближайшего);
  отрицательный — вверх. Один вызов прокручивает до 40 щелчков, каждому соответствует отдельное
  событие колеса — столько же, сколько сделал бы пользователь. Больший `deltaY` молча обрезается до
  40 щелчков, а меньше 20 px не прокручивает вовсе, хотя ответ — успех: проверяй снимком.
  Горизонтальная прокрутка не поддерживается (`InputRejected` при `deltaX != 0`); для горизонтальных
  списков используй drag.
- **`<f>_type`**: на Windows — точные символы независимо от раскладки (Unicode-события). На macOS —
  позиции клавиш US-раскладки: символы вне US ASCII отклоняются (`UnsupportedCharacter`), а при
  не-US раскладке латиница может прийти другими буквами — проверяй снимком. `\n` и `\r\n` — Enter,
  `\t` — Tab, `\b` — Backspace; прочие управляющие символы отклоняются. За один вызов — до 1000
  UTF-16 единиц (символ вне BMP — две, флаги и составные эмодзи — больше; длиннее — `InvalidAction`);
  длинный текст дели на части и между частями проверяй результат снимком. Если текст не появился — проверь фокус (кликни в поле).
- **`<f>_key`**: до 6 имён через запятую — модификаторы `ctrl`, `alt`, `shift`, `win` (или
  `meta`, `cmd`), клавиши `enter`, `tab`, `esc`, `backspace`, `delete`, `insert`, `space`,
  `home`, `end`, `pageup`, `pagedown`, стрелки `up`, `down`, `left`, `right`, `minus`, `equals`,
  `comma`, `period`, `slash`, `semicolon`, `quote`, `backslash`, `bracketleft`, `bracketright`,
  одиночные символы без Shift (`a`, `1`, `-`; не `!` и не `+`), `f1`–`f24`.
  Примеры: `"ctrl,s"`, `"f5"`, `"enter"`, `"win"`. Неизвестное имя — отказ `UnsupportedKey`,
  а не молчаливый пропуск.

Комбинации с `win`, `alt`, `ctrl` меняют состояние всей системы. Не используй `win` без нужды и не
нажимай деструктивные связки вроде `"alt,f4"` без явной просьбы пользователя: код их не блокирует,
ответственность на тебе. `ctrl+alt+del` синтетически недоступна.

## Владение и жизненный цикл

- Захват принадлежит ходу агента, который его открыл. Пока захват держит другой ход,
  захват, снимки, ROI, ввод и release любого семейства отвечают `CaptureOwnedByAnotherTurn`:
  своего захвата у тебя нет. Не повторяй вызовы, сообщи пользователю, что компьютер занят; захват
  другого хода освободится, когда тот закончится. `computer_status` и `window_list` доступны.
- `StoppedByUser` — пользователь нажал «Стоп»: инструментами компьютера в этом ходе больше не
  пользуйся.
- Одобренный вызов привязывает ввод к кадру, на котором пользователь видел действие. Если кадр
  сменился, ответ будет `CaptureChangedSinceApproval` — сделай свежий снимок и повтори вызов.
- Смена режима или цели — `_capture` нужного семейства с новыми параметрами; ввод перевооружается
  автоматически одобренным вызовом.

## Отказы и восстановление

| Отказ | Что делать |
|---|---|
| `Disabled`, `ComputerUseUnavailable`, `Unavailable` | Фича выключена или устройство недоступно: проверь `computer_status` (`blockers`), не повторяй вслепую. |
| `PermissionLost`, `NotArmed`, `ModeNotAllowed` | Права ОС отозваны или режим запрещён: проверь `computer_status`, попроси пользователя восстановить доступ. |
| `InvalidAction`, `InvalidRoi`, `InvalidTile`, `InvalidCrop` | Неверные аргументы (например, текст длиннее 1000 UTF-16 единиц, больше 6 клавиш, `roi` и `tile` вместе): исправь вызов. |
| `RecordingDisabled`, `InvalidRecording`, `RecordTimedOut` | Запись выключена тоглом, аргументы вне пределов или устройство не ответило: обойдись снимками / исправь аргументы / проверь `computer_status`. |
| `CaptureModeMismatch` | Активный захват другого семейства: используй его инструменты или захвати своим `_capture`. |
| `UnknownWindow`, `UnknownMonitor` | Окно закрыто или монитора нет: `window_list` / `computer_status` и выбери заново. |
| `OutsideRoi` | Точка или прямоугольник вне активной ROI: пересчитай по кадру ROI, расширь или сбрось ROI (`<f>_roi {clear:true}`). |
| `NotCapturing`, `CaptureEnded` | Захвата нет или он закрыт: вызови `<f>_capture` заново. |
| `NoMasterFrame` | Нет кадра для zoom или ROI: сделай `<f>_screenshot`. |
| `UnknownCapture`, `CaptureExpired` | `captureId` от прежнего захвата или вытесненного кадра: свежий `<f>_screenshot`, затем zoom без старого `captureId`. |
| `CaptureRefused` | Захват не открылся: проверь `computer_status`. Непустые `blockers` или `captureAvailable: false` — нет прав ОС: попроси пользователя выдать их и не повторяй. `windowCaptureAvailable: false` — используй `computer_capture`. |
| `CaptureFailed` | Система не отдала кадр: повтори снимок один раз, затем захвати заново или выбери другую цель. |
| `RegionOutOfBounds` | Точка/область вне последнего кадра: свежий снимок, пересчёт координат. |
| `StaleFrame`, `TargetResized` | Экран или окно изменились: свежий снимок, при смене геометрии — повторный захват. |
| `TargetClosed`, `TargetMinimized`, `ClientAreaUnavailable`, `TargetNotForeground`, `ActivationFailed` | Цель недоступна: проверь `window_list` и выбери окно заново. |
| `SelfCaptureNotAllowed` | Окно Heartbeat захватывать нельзя: выбери другое окно. |
| `EncodingTooLarge` | Кадр не помещается в бюджет: уменьши область или возьми тайл. |
| `CaptureChangedSinceApproval` | Кадр устарел после одобрения: свежий снимок и повтор вызова. |
| `CaptureOwnedByAnotherTurn` | Компьютер занят другим ходом: не повторяй, сообщи пользователю. |
| `StoppedByUser` | Пользователь остановил: не продолжай. |
| `UnsupportedKey` | Проверь имя клавиши по списку выше. |
| `UnsupportedCharacter` | Символ нельзя набрать на этом хосте (на macOS — всё вне US ASCII; везде — управляющие символы, кроме перечисленных): переформулируй текст. |
| `InputRejected` | Действие отклонено платформой (горизонтальный скролл, отказ системы во время набора): свежий снимок — часть текста могла появиться, затем измени способ. |
| `CleanupTimedOut` | `<f>_release` не дождался закрытия: проверь `computer_status`; захват всё равно освободится в конце хода. |
| `UnexpectedOutput`, `ComputerUseToolFailed`, `UnknownTool` | Внутренний сбой или неизвестное имя инструмента: проверь `computer_status`, не повторяй вслепую, сообщи пользователю. |
| `InputTimedOut`, `FrameTimedOut`, `CaptureTimedOut` | Устройство не ответило вовремя, и захват уже закрыт. Действие могло примениться частично: новый `<f>_capture`, проверь результат и досылай только недостающее — повтор вслепую задвоит текст. При повторном таймауте — стоп и отчёт. |

## Практика

1. Один сценарий — один захват: не переключай режимы без необходимости, каждый захват прячет
   окно сессии и мешает пользователю.
2. После каждого ввода — свежий снимок и проверка эффекта; не строй цепочки вслепую.
3. Не трогай окна и данные, не относящиеся к задаче: пользователь работает параллельно, его
   раскладка, фокус и позиции окон могут измениться в любой момент.
4. Работаешь с частью экрана — задай ROI: кадры меньше и чётче, а ввод не уйдёт за её пределы.
5. `clientAreaOnly` у `window_capture` даёт кадр без рамки окна — удобен для точных координат содержимого.
6. Тесты UI веди в своём тестовом окне (Блокнот, песочница), а не в рабочих приложениях.
