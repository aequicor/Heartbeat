# Computer use: работа движка с инструментами `computer_*`

Инструменты управляют реальным экраном пользователя. Это привилегия, а не песочница: каждое
действие видно человеку, а ошибка ввода попадает в его окна. Фича доступна только на Desktop
Windows/macOS и включена, если инструменты появляются в наборе; сам факт вызова — уже одобренная
операция, поэтому работай аккуратно и экономно.

## Обязательный порядок работы

1. **`computer_status`** — всегда первым вызовом: права, мониторы, активный захват, `inputArmed`.
2. **`computer_windows`** — при выборе цели; в ответе идентификаторы, границы и `clientBounds`.
3. **`computer_capture`** — старт или смена захвата:
   - работа в границах одного приложения — режим `window` с `windowId` из списка (точнее по
     пикселям, ввод гарантированно остаётся в окне);
   - задача между приложениями или по всему экрану — режим `desktop`; несколько мониторов
     выбираются через захват полного стола (кадр покрывает объединение мониторов).
   - первый кадр приходит в ответе на захват — отдельный снимок не нужен.
4. **`computer_screenshot`** — свежий кадр; **`computer_zoom`** — чтение мелкого текста.
5. **Ввод** — `computer_click`, `computer_drag`, `computer_scroll`, `computer_type`, `computer_key`.
6. **`computer_release`** — сразу по завершении работы; кадры сессии удаляются. Захват также
   освобождается автоматически в конце хода.

После каждого шага изменения экрана делай свежий `computer_screenshot`: решения по устаревшему
кадру — главная причина ложных кликов.

## Координаты и кадры

- Координаты ввода — пиксели **последнего полученного кадра** (снимок, zoom, кроп). Другое
  пространство задаётся явно: `space` = `preview` | `master` | `normalized` | `screen`.
- `computer_screenshot` возвращает уменьшенный кадр и сетку тайлов; `tile: "колонка:строка"`
  (с нуля) и `regionX/Y/Width/Height` в master-пикселях режут кадр, `computer_zoom` вырезает
  область master в нативном разрешении — им и читай мелкий текст, не угадывай по превью.
- `RegionOutOfBounds` — точка или область вне последнего кадра: возьми новый снимок и пересчитай
  координаты, не двигай точку наугад.
- `StaleFrame` / `TargetResized` — экран изменился: свежий снимок обязателен перед повтором.

## Ввод

- **`computer_click`**: `count` 1–3 (двойной/тройной клик — `count`, не повтор вызова). Правый и
  средний клики — через `button`.
- **`computer_drag`**: перетаскивание между двумя точками одного кадра; для выделения текста
  сначала щёлкни в позицию, потом тащи между пикселями одной строки.
- **`computer_scroll`**: `deltaY` в пикселях, 40 px = один «щелчок» колеса; отрицательный — вверх.
  Один вызов прокручивает до 40 щелчков, каждому соответствует отдельное событие колеса — столько
  же, сколько сделал бы пользователь. Горизонтальная прокрутка не поддерживается (`InputRejected`
  при `deltaX != 0`); для горизонтальных списков используй drag.
- **`computer_type`**: точные символы независимо от раскладки (Unicode-события на Windows);
  `\n` — Enter, `\t` — Tab. За один вызов — до 1000 символов; длинный текст дели на части и между
  частями проверяй результат снимком. Если текст не появился — проверь фокус (кликни в поле).
- **`computer_key`**: имена через запятую — модификаторы `ctrl`, `alt`, `shift`, `win` (или
  `meta`, `cmd`), клавиши `enter`, `tab`, `esc`, `backspace`, `delete`, `insert`, `space`,
  `home`, `end`, `pageup`, `pagedown`, стрелки, `minus`, `equals`, `comma`, `period`, `slash`,
  `semicolon`, `quote`, `backslash`, `bracketleft`, `bracketright`, одиночные символы, `f1`–`f24`.
  Примеры: `"ctrl,s"`, `"f5"`, `"enter"`, `"win"`. Неизвестное имя — отказ `UnsupportedKey`,
  а не молчаливый пропуск.

Комбинации с `win`, `alt`, `ctrl` меняют состояние всей системы. Не используй `win` без нужды,
запрещены деструктивные связки (`alt+f4`, `ctrl+alt+del` недоступен синтетически) — закрывай
чужие приложения только явной просьбой пользователя.

## Владение и жизненный цикл

- Захват принадлежит ходу агента, который его открыл: чужой захват отвечает
  `CaptureOwnedByAnotherTurn` — сначала освободи свой (`computer_release`) или работай со своим.
- `StoppedByUser` — пользователь нажал «Стоп»: инструментами компьютера в этом ходе больше не
  пользуйся.
- Одобренный вызов привязывает ввод к кадру, на котором пользователь видел действие. Если кадр
  сменился, ответ будет `CaptureChangedSinceApproval` — сделай свежий снимок и повтори вызов.
- Смена режима или цели — обычный `computer_capture` с новыми параметрами; ввод перевооружается
  автоматически одобренным вызовом.

## Отказы и восстановление

| Отказ | Что делать |
|---|---|
| `Unavailable` | Фича или устройство недоступны: проверь `computer_status` (`blockers`), не повторяй вслепую. |
| `NotCapturing` / `NoMasterFrame` | Захват закрыт: вызови `computer_capture` заново. |
| `RegionOutOfBounds` | Точка/область вне последнего кадра: свежий снимок, пересчёт координат. |
| `StaleFrame`, `TargetResized` | Экран или окно изменились: свежий снимок, при смене геометрии — повторный захват. |
| `TargetClosed`, `TargetMinimized`, `ClientAreaUnavailable` | Цель недоступна: выбери другое окно из `computer_windows`. |
| `CaptureChangedSinceApproval` | Кадр устарел после одобрения: свежий снимок и повтор вызова. |
| `CaptureOwnedByAnotherTurn` | Захват принадлежит другому ходу: работай со своим захватом. |
| `StoppedByUser` | Пользователь остановил: не продолжай. |
| `UnsupportedKey` | Проверь имя клавиши по списку выше. |
| `UnsupportedCharacter` | Символ не проецируется на клавиатуру (эмодзи…): переформулируй текст. |
| `InputRejected` | Действие отклонено платформой (например, горизонтальный скролл): измени способ. |
| `InputTimedOut` | Устройство не ответило в срок: один повтор после свежего снимка, затем стоп и отчёт. |
| `PermissionLost` | Права ОС отозваны: попроси пользователя восстановить, проверь `computer_status`. |
| `Timeout` | Операция не завершилась вовремя: проверь статус и повтори один раз. |

## Практика

1. Один сценарий — один захват: не переключай режимы без необходимости, каждый захват прячет
   окно сессии и мешает пользователю.
2. После каждого ввода — свежий снимок и проверка эффекта; не строй цепочки вслепую.
3. Не трогай окна и данные, не относящиеся к задаче: пользователь работает параллельно, его
   раскладка, фокус и позиции окон могут измениться в любой момент.
4. `clientAreaOnly` даёт кадр без рамки окна — удобен для точных координат содержимого.
5. Тесты UI веди в своём тестовом окне (Блокнот, песочница), а не в рабочих приложениях.
