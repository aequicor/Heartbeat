# Прототип UI: `$ARGUMENTS`

Справочник — [design/README.md](../../../design/README.md): иерархия файлов и кадров (раздел 2), правила JSON (4.4),
таблица переноса в Compose (4.5). Здесь — исполнимая последовательность.

## 0. Нужен ли этап

Обязателен для нового экрана, режима, диалога, флоу, нового или изменённого `Hb*`-компонента, заметного изменения
раскладки, нового перехода или анимации. Без него — логика без визуального эффекта, тексты, багфикс до уже
согласованного макета, значение токена (тогда обнови переменную в `design/system/heartbeat.lib.pen`, если она есть),
исправление дефекта e2e, возвращающее задуманное поведение. У экрана нет `.pen` — макет только затронутых экранов
и состояний. Сомневаешься — делай макет. pen.dev или снимок окна недоступны (Linux, Codex без снимка) — этап не
пропускается: скажи пользователю, что картинку не видел, и попроси проверить кадры до согласования.

## 1. Контекст

1. `.claude/rules/design-system.md` — принципы эталона: плотность, типографика, тихие состояния, режимы вместо экранов.
2. `design/system/heartbeat.lib.pen` и `design/features/<feature>/` — если есть.
3. `.pen` перечитывай с диска перед каждой правкой: пользователь мог поправить его в pen.dev, его правки авторитетны.

## 2. Макет

- Файл `design/features/<feature>/<feature>.pen`, секции `Screens` / `Components` / `Transitions` / `Notes`,
  кадры на **всех форм-факторах** `<Screen> / <State> / Phone` (390×844), `/ Tablet` (834×1112), `/ Desktop` (1280×800),
  при отличиях `/ Desktop compact` (420) — README 2.5; `hb:host` = `mobile` для Phone и Tablet, `desktop` для Desktop;
  Desktop-only фича — только Desktop с причиной в заметке; `id` без `/`; тёмная тема — `ref` на кадр с `theme`; `width`/`height` без `$`-переменных (README 4.4).
- Составные компоненты на экране — копия структуры из `heartbeat.lib.pen` (не `ref`: внутри экземпляра нельзя двигать мышью); `ref` — иконки, иллюстрации, разделитель; токены — `$`-переменные библиотеки. Чего нет — сначала компонент или предложение токена
  (`proposal.<name>` + заметка) в библиотеке. Адресация через алиас: `"ref": "hb:<id>"`, `"$hb:<переменная>"`,
  `"theme": {"hb:mode": "dark"}` (README 2.4); иконки — только `ref` на `hb:hb-icon-*`, шрифт —
  `$hb:typography.family`; справочник стилей и компонентов — `design/system/design-system.pen`, образцы —
  `design/features/*`.
- Заметка `Поведение · <Screen>` описывает границы `720` и `1200` (сайдбар → drawer, список → раздел, панели).
- Все видимые состояния отдельными кадрами: пустое, загрузка, ошибка, длинный русский текст, значимые hover/selected/
  disabled/фокус. Навигационный переход — раскадровка и заметка `trigger / transition`;
  микро-анимация — заметка `trigger / duration / easing / reduced` (README 2.3).
- Правки JSON — по README 4.4: `version` и чужие узлы не трогать, `id` стабильные, раскладка свободная (`layout: none`,
  `x`/`y`), поведение при растяжении, прокрутке и других размерах — заметка `Поведение · <Screen>` под экраном.

## 3. Посмотри сам

Открой файл в pen.dev (`open -g -a Pen <file>`; уже открытую вкладку сначала закрой `File → Close Tab` —
приложение не перечитывает файл с диска) и сними окно: Claude Code desktop — computer-use в фоне по
`dev.pencil.desktop` (`app_screenshot`/`app_zoom`), панель свойств слоя — проверка размеров и привязок; Heartbeat —
`computer_status` → `window_list` → `window_capture` → `window_screenshot`/`window_zoom` → `window_release`
(скилл `computer-use`; переходы по холсту — ввод, он подтверждается по режиму безопасности). Приблизь каждый
изменённый кадр, исправь перекрытия, обрезанный текст, неровные отступы, лишние элементы. Файл не открылся —
откати правку и сделай её меньшими шагами. Снимка нет — правило §0.

## 4. Согласование

1. Коммит `design(<feature>): макет <что>` (в draft PR — отдельный шаг по `open-pr`).
2. Пользователю: путь к файлу, список кадров, решения и открытые вопросы одним сообщением. Жди явного «согласовано».
3. Правки словами — внеси, проверь снимком, покажи снова. Правки руками в pen.dev — перечитай файл, закоммить
   `design(<feature>): правки пользователя`, учти в реализации.
4. В описании PR — раздел «Дизайн» (шаблон `open-pr`): файл, кадры, SHA согласованного коммита, кто и когда
   согласовал; после переписывания истории SHA обнови.

Без согласования UI-код не пиши: `pr-review` считает это блокером.

## 5. Реализация и сверка

1. Перенос по таблице README 4.5: переменные → `HbTheme.*`, `ref` → `Hb*`, кадры-состояния → состояния стора
   и `@Preview`, раскадровки → `NavTransition` и `HbTheme.motion`. Число без переменной — сначала токен с KDoc.
2. Сверка: снимок desktop (`./gradlew :platform-main:desktop:run`) или рендер превью jvmTest рядом с кадрами pen.dev.
   Ошибка — правь код; сознательное расхождение — правь макет отдельным коммитом и перечисли в разделе «Дизайн».
3. Макет живой: любые следующие UI-правки этого экрана меняют `.pen` в том же PR.
