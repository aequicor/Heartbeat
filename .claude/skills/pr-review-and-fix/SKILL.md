# PR review and fix

Оркестрация двух скиллов: [pr-review](../pr-review/SKILL.md) и [pr-fix](../pr-fix/SKILL.md).
Процедуры шагов — в них; здесь только цикл, передача находок и условия остановки.
Подпись `/reviewed` ставит только `pr-review` и только на SHA, который он сам проверил.

## Цикл

```text
раунд 0:  pr-review (полный, с учётом прошлых маркеров)
          ├─ подписан → готово
          └─ есть что исправлять → раунд 1
раунд k:  pr-fix (правки → коммит Addresses-Review → push → ответы в тредах)
          → pr-review (инкрементально: только новый коммит + сквозная проверка)
          ├─ подписан → готово
          └─ снова находки → раунд k+1 (k ≤ 3)
```

1. **Ревью.** Выполни `pr-review` для PR `<N>`. Его комментарий с находками публикуется как обычно — это журнал
   для людей и маркер инкрементальности для следующих раундов.
2. **Что исправлять.** Вход для `pr-fix`: все blocker и major из ревью, упавший CI, нерешённые треды и
   `CHANGES_REQUESTED`. minor — только если правка локальна и не требует решения по дизайну; остальные minor
   оформи GitHub issues (решение **issue** в `pr-fix`) и дай ссылки в итоговом ответе. Утечки ресурсов исправляются
   всегда, независимо от уровня находки. Находки уже в контексте — не перечитывай их из комментария,
   но треды и CI собери по шагу 1 `pr-fix`: люди могли написать что-то новое.
3. **Исправление.** Выполни `pr-fix` для этого списка. Его шаг 6 (ревью и подпись) — это шаг 1 следующего раунда,
   не запускай `pr-review` дважды.
4. **Повтор** до подписи или до условия остановки.

## Остановка без подписи

Прекращай цикл и отдай решение пользователю, если:

- после 3 раундов исправлений всё ещё есть блокеры;
- та же находка (тот же `file:line` и суть) вернулась после исправления — правка не помогла, нужен другой подход;
- `pr-fix` отклонил (decline) блокер — спор о правиле или дизайне решает пользователь;
- замечание человека неясно, требует изменения цели PR или выходит за его рамки;
- CI падает по причине вне PR (инфраструктура, флак) — перезапуск CI не делай без просьбы;
- head сдвинулся из-за чужого push во время раунда — начни раунд 0 заново только один раз, затем остановись.

## Итог пользователю

- Вердикт: подписан `<sha>` (и `reviewDecision`) или остановлен — причина.
- По раундам: находки → fixed / declined, SHA коммитов исправлений.
- Issues для оставшихся minor, declined с обоснованием; ссылки на комментарии ревью и PR.
