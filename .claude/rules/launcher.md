# Лаунчер desktop и его слоты (`platform-main/launcher`, `platform-main/launcher-selector`)

Обе части — чистая Java 17 без зависимостей и без Kotlin: они запускаются раньше stdlib из бандлов, а у Java-модулей нет detekt.

- **Цепочка запуска установленного приложения**: `SelectorMain` (в установщике, неизменный) → лаунчер из слота A/B или
  встроенный → поезд. Селектор — единственный проектный код на classpath установщика (`CollectPlatformJars` проверяет:
  проектные классы допустимы только в пакете `io.aequicor.heartbeat.selector`). Лаунчер — артефакт поезда `kind=launcher`
  (`assembleLauncher`) и файл установщика `resources/launcher-embedded.seed` (`-Dheartbeat.selector.embedded`): запасной
  вариант, когда слотов нет или ни один не прошёл проверку.
- **Селектор держит минимум**: выбор слота, счёт пробных запусков, проверка подписи, откат. Не добавляй в него сеть,
  JSON и логику поезда — его нельзя исправить без полной переустановки. Формат `slots/state.properties` и
  `slot.properties` версионируется полем `format`; файл новее поддерживаемого не читается и не перезаписывается,
  неизвестные поля сохраняются. Новое поле — только добавлением.
- **Слот**: `slots/{A,B}/launcher.jar` + `slot.properties` (запись манифеста с подписью). Слот пробный, пока он
  не подтверждён: подтверждение — вход лаунчера в `main` приложения (`LauncherMain.start(args, applicationStarted, stager)`).
  Два запуска пробного слота без подтверждения — слот отвергается (SHA-256 в `bad`), запускается подтверждённый или
  встроенный. Состояние меняет только владелец (`slots/owner.lock`), остальные процессы только читают. Селектор не должен
  мешать запуску: ошибка чтения или записи состояния даёт встроенный лаунчер, а слот, который сейчас не прочитать
  (антивирус, занятый файл), пропускается на этот запуск и не отвергается — отвергают только окончательные причины
  (подпись, тип, уровень, хэш, повреждённый jar, нет класса или метода запуска).
- **Загрузчик лаунчера** (`SlotLauncher`): классы пакета `io.aequicor.heartbeat.launcher` берутся только из jar слота,
  без возврата к родителю; `Instrumentation` лаунчеру передаёт селектор. Между загрузчиками селектора и лаунчера нет
  общих классов — только типы JDK (`Predicate<Map<String,String>>`, `Runnable`, системные свойства `heartbeat.*`).
- **Подпись Ed25519**: подписывается запись `heartbeat-launcher-record-v1` (id, version, sha256, kind, launcherApi).
  Те же байты строят `SlotRecord.canonical()` селектора и `launcherRecordCanonical` в build-logic; тестовый вектор в
  `SlotRecordTest` и `LauncherRecordTest` менять нельзя без нового заголовка записи. Доверенные ключи (до четырёх) —
  `trusted-keys.txt` селектора (основной и запасной; закоммичены, `-Pheartbeat.trustedKeysFile=<файл>` заменяет их только
  для локального e2e с одноразовыми ключами, сборка падает на отсутствующем или неверном файле); приватный ключ CI
  (PKCS#8 Base64) — секрет окружения GitHub `launcher-signing`, в сборке переменная окружения
  `HEARTBEAT_LAUNCHER_SIGNING_KEY`, не Gradle-свойство. Без ключей селектор
  не доверяет ни одному слоту. Уровень `launcherApi` монотонный (`-Pheartbeat.launcherApi`): слот ниже самого высокого
  подтверждённого не принимается. Порядок задаёт только уровень, `version` (id поезда) не упорядочивается: исправление
  безопасности в лаунчере обязано поднять уровень, иначе подписанный старый лаунчер с тем же уровнем пройдёт проверку.
  Утёкший ключ позволил бы подписать огромный уровень и навсегда заблокировать слоты — отзыва ключа нет, лечение — новый
  установщик с другими ключами. Селектор и лаунчер собираются с `--release 17`: селектор нельзя исправить без переустановки.
- **Обновление слота** делает сам лаунчер активного поезда: `SlotUpdate` предлагает jar `kind=launcher` селектору,
  `Selector.stageUpdate` копирует его в соседний слот (временный файл, SHA-256, атомарный rename, запись слота
  последней) и делает пробным. Подтверждённый и работающий слоты не перезаписываются; идёт пробный запуск — обновление ждёт.
- **Пробный слот не трогает необратимые данные**: `heartbeat.slot.trial=true` — `Launcher` откладывает откат с
  восстановлением БД и активацию ожидающего поезда до подтверждения слота. Отказ запуска из-за такой отсрочки
  (повреждённый поезд) лаунчер помечает `heartbeat.slot.deferred=true` и отпускает `instance.lock`: селектор освобождает
  пробный слот без отметки о крахе (`Selector.release`) и запускает подтверждённый лаунчер в том же процессе, который
  выполнит откат. Состояние лаунчера новее поддерживаемого формата `LauncherMain` не читает и не меняет: приложение
  стартует из seed (деградированный старт: версию схемы БД он не сверяет, а новый лаунчер мог уже мигрировать БД —
  осознанный выбор «открыть приложение», риск принят). Пробный слот, который сейчас не прочитать, остаётся пробным:
  на этот запуск стартует подтверждённый. Явный `"launcherApi": null` в манифесте равен отсутствию поля.
- **Проверка на упакованном приложении** (macOS, окна открываются): `scripts/e2e_launcher_slots.py` — слоты A/B,
  подтверждение, обновление в соседний слот, отказ для старого и чужого лаунчера, слот, который не запускается; нужны
  одноразовые ключи (`scripts/e2e_launcher_slots/Keys.java`), сборка с ними описана в docstring скрипта. Не для релизных ключей.
- **`platformApi` поезда = 2** (`Launcher.PLATFORM_API`, `INSTALLED_PLATFORM_API` в app-update): лаунчер уровня 1 положил бы
  jar лаунчера в classpath приложения. Новое несовместимое изменение формата поезда — повышай уровень и в манифесте.
- **Окно-хост embedded-пути** (Windows x64): `WS_EX_COMPOSITED` нужен только сцене лончера (GDI и owner-drawn
  кнопки). Когда встроенная Studio представила первый кадр, лаунчер снимает стиль (`hb_host_release_composition`):
  композитное окно собирает дерево через внеэкранный GDI-битмап, и каждая рамка ускоренной поверхности Compose
  проходит лишнюю копию — интерфейс тормозит всю сессию. Транзитные стили handoff (`WS_EX_LAYERED`) тоже не должны
  переживать представленную рамку: снятие делается под нативной крышкой, а представленной подтверждается следующая
  нарисованная рамка. Стили окна ставит нативный бинарь лончера, поэтому такая правка уезжает только с новой
  сборкой установщика (слоты обновляют лишь `launcher.jar`), а не поездом.
