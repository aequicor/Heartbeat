# CI (`.github/workflows`)

CI проверяет необходимый минимум: джоба существует, только если проверяет то, что нельзя проверить локальным
`verify`, и запускается, только когда изменение может её сломать. Правила пользования CI — раздел «CI» в `AGENTS.md`.

| Workflow | Когда | Что |
|---|---|---|
| `commit-policy.yml` | каждый PR, включая draft | токенный бюджет каждого коммита — обязательная проверка |
| `scripts.yml` | PR меняет `scripts/`, проверяемый ими workflow или ресурсы Pi | unit-тесты Python-инструментов |
| `harness-compiler.yml` | не-draft PR меняет упакованный компилятор харнесса | release-образ и проба на macOS и Windows; мобильная компиляция — только при изменении исходников харнесса |
| `review-approve.yml`, `close-fixed-issues.yml` | `/reviewed`, мерж PR | действия бота, без сборки |

Новые workflow, джобы, шаги сборки, платформы, матрицы и триггеры, расширение `paths` — только с согласия
пользователя. Изменяя или добавляя workflow:

- **Commit policy** не фильтруй по путям, не пропускай условием `if` и не отключай. Пропущенная джоба отчитывается
  успехом поверх прежнего падения, поэтому обязательные проверки не пропускаются ни по событию, ни по путям.
- **Триггер** — `pull_request`. Не `push` в рабочие ветки: вместе с PR это двойной прогон. `push` в `master` —
  только если результат нужен после мержа и не повторяет проверку PR (она уже собирает merge с `master`).
  Тяжёлые джобы не запускаются на draft: `types: [opened, synchronize, reopened, ready_for_review]` и
  `if: github.event_name != 'pull_request' || !github.event.pull_request.draft`.
- **`paths`** — только файлы, меняющие результат проверки; тесты, ресурсы, UI, схемы и документацию исключай
  (`!…`). Шаг, нужный лишь части путей, гейти по `git diff` merge-коммита PR, а не отдельным workflow.
- **Объём** — только затронутые модули и задачи, не `build`/`allTests`/`check` всего проекта; повторение того,
  что делает локальный `verify`, в CI не нужно. Связанные шаги — в одной джобе: новая джоба — это новый раннер
  и новый прогрев Gradle.
- **Платформы** — `ubuntu-latest`, если результат не зависит от ОС; macOS/Windows — только для поведения,
  которое отличается на этой ОС (упаковка, нативный код, iOS). Матрица — без дублирующих комбинаций.
- **Каждая джоба** — `timeout-minutes`, минимальные `permissions`, `concurrency` с `cancel-in-progress: true`
  по ветке или номеру PR.
- **Диагностические и временные workflow** (триггер на свою ветку, отладочные матрицы, выгрузка логов) не создавай.
  Если поведение проверяется только на чужой ОС — спроси пользователя; с его согласия — один прогон,
  после которого временный workflow удаляется из ветки до ревью.
- Изменённый workflow проверь локально: синтаксис YAML и выражения, `git diff`-гейты — на временном репозитории.
