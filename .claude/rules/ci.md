# CI (`.github/workflows`)

CI проверяет необходимый минимум: джоба существует, только если проверяет то, что нельзя проверить локальным
`verify`, и запускается, только когда изменение может её сломать. Правила пользования CI — раздел «CI» в `AGENTS.md`.

**Проверка PR — только быстрые проверки и сборки отдельных модулей.** Долгие сборки — приложение целиком,
release-образ и упаковка, нативные рантаймы, `build`/`allTests`/`check` всего проекта — в проверку PR не входят:
только `workflow_dispatch`, запуск — по решению пользователя.

| Workflow | Когда | Что |
|---|---|---|
| `commit-policy.yml` | каждый PR, включая draft | токенный бюджет каждого коммита — обязательна по политике репозитория (в ruleset не required check) |
| `scripts.yml` | PR меняет `scripts/`, проверяемый ими workflow или ресурсы Pi | unit-тесты Python-инструментов |
| `harness-mobile-hosts.yml` | не-draft PR меняет common/Android/iOS-исходники харнесса, версии или `build-logic` | модуль `:features:harness:impl` под Android и iOS |
| `harness-compiler.yml` | вручную, по решению пользователя | долгая сборка: release-образ и проба компилятора харнесса на macOS и Windows |
| `review-approve.yml`, `close-fixed-issues.yml` | `/reviewed`, мерж PR | действия бота, без сборки |

Новые workflow, джобы, шаги сборки, платформы, матрицы и триггеры, расширение `paths` — только с согласия
пользователя. Изменяя или добавляя workflow:

- **Commit policy** не фильтруй по путям, не пропускай условием `if` и не отключай. Пропущенная джоба отчитывается
  успехом поверх прежнего падения, поэтому обязательные проверки не пропускаются ни по событию, ни по путям.
- **Триггер** сборки модуля — `pull_request`, долгой сборки — только `workflow_dispatch`. Не `push` в рабочие
  ветки (вместе с PR это двойной прогон) и не `push` в `master` (проверка PR собирает merge с `master` на момент
  своего запуска). Бот-workflow (`issue_comment`, `pull_request_target`) код PR не собирают и не выгружают.
  Сборки на macOS/Windows не запускаются на draft: `types: [opened, synchronize, reopened, ready_for_review]` и
  `if: ${{ !github.event.pull_request.draft }}`.
- **`paths`** — только файлы, меняющие результат проверки: исходники и build-файлы собираемых модулей и API в их
  classpath; тесты, ресурсы, UI, схемы и документацию, которые проверка не использует, исключай (`!…`).
- **Объём** — задачи отдельных затронутых модулей (`:<module>:compile…`, `:<module>:jvmTest`), которые не покрывает
  локальный `verify` (например, iOS для агентов на Windows). Связанные шаги — в одной джобе: новая джоба — это
  новый раннер и новый прогрев Gradle.
- **Платформы** — `ubuntu-latest`, если результат не зависит от ОС; macOS/Windows — только для поведения,
  которое отличается на этой ОС (упаковка, нативный код, iOS). Матрица — без дублирующих комбинаций.
- **Каждая проверка PR** — `timeout-minutes`, минимальные `permissions`, `concurrency` с `cancel-in-progress: true`
  на PR: номер PR или `github.ref` (для `pull_request` это `refs/pull/<N>/merge`). Бот-workflow задают
  `concurrency` по своей семантике или обходятся без неё (approve не отменяется).
- **Диагностические и временные workflow** (триггер на свою ветку, отладочные матрицы, выгрузка логов) не создавай.
  Если поведение проверяется только на чужой ОС — спроси пользователя; с его согласия — один прогон,
  после которого временный workflow удаляется из ветки до ревью.
- Изменённый workflow проверь локально: синтаксис YAML и выражения (`actionlint`, если установлен).
